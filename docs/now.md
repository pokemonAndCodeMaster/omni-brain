# 当前实验工作台

> 最近更新：2026-07-25。

## 当前状态

知识摄入已能在发布前隔离候选、定向读取直接事实源，并形成局部业务—代码纵切；最近一次前向 Trial 仍把可独立维护的知识压进少数总览页，并把局部可靠答案说成整体完整。当前第七版状态是 `implemented_content_first_v7_awaiting_forward_test`；正式知识仍为空，也没有参考答案或业务评分点进入本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、Agent 覆盖声明、固定根入口、内容声明契约和结构门禁；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 第七版能否让弱模型按独立变化划分知识单元、保留有证据的上级层级，并把授权材料中的未整理内容带回编织循环；
- 多部分问题能否稳定区分“局部可靠”和“整体完整”，不把明确未知误标为可靠；
- 共享实现、公共依赖和占位边界能否进入合适的公共能力页或知识缺口页；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。

## 下一动作

冻结第七版基线后，用完全相同的真实需求和来源运行前向 Trial。主要检查知识层级与独立落点、授权材料内容回环、可信度自评、公共能力边界和软件说明能否同时成立；结构检查继续只作辅助诊断。候选在通过人工内容审查前不发布、不升级能力状态。
