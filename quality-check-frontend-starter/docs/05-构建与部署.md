# 05. 构建与部署

## 一、本地生产构建

```bash
npm run build
```

输出：

```text
dist/
├── index.html
└── assets/
```

本地验证：

```bash
npm run preview
```

打开：

```text
http://localhost:4173
```

不要用文件协议直接打开 `dist/index.html`，路由和资源路径可能异常。

## 二、为什么 Nginx 要配置 `try_files`

Vue Router 使用 History 模式。访问：

```text
/manual-qc/deliveries
```

浏览器刷新时，Nginx 必须返回 `index.html`，再由 Vue Router 接管。

本工程：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```


## 四、接真实 API 的 Docker 构建

Vite 环境变量在“构建时”写入前端包，不是在 Nginx 启动时动态读取。

```bash
docker build \
  --build-arg VITE_USE_MOCK=false \
  --build-arg VITE_API_BASE_URL=/api/v1 \
  -t quality-check-frontend:prod .
```

生产建议通过统一网关把：

```text
/        → 前端 Nginx
/api/    → FastAPI
```

放在同一域名下，减少 CORS 和 Cookie 问题。

## 五、直接部署到已有 Nginx

```bash
npm ci
npm run build
sudo mkdir -p /var/www/quality-check
sudo cp -r dist/* /var/www/quality-check/
```

Nginx：

```nginx
server {
    listen 80;
    server_name quality-check.example.com;
    root /var/www/quality-check;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 六、CI 建议

每次合并至少执行：

```bash
npm ci
npm run type-check
npm run build
```

后续加入测试后：

```bash
npm run test
npm run test:e2e
```

## 七、缓存注意事项

带 Hash 的资源文件可以长缓存：

```text
assets/index-xxxx.js
assets/index-xxxx.css
```

`index.html` 不建议长缓存，否则可能一直引用旧 Hash。
