## 2. 需求审查

原始诉求关键点（`review-input.md` 第 7–16 行）：

1. 公共多维聚合与展开表格，**不把维度关系写死**；用户可选择某个维度聚合，再沿其他维度展开；
2. **每个合法统计数值单元格都可以成为详情入口**，在当前行数据范围内沿剩余维度继续分析，
   **而不是只允许某一个"缺口"指标下钻**；
3. 详情可以继续使用聚合展开表格，结合可复用统计卡片和图表完成多维呈现、筛选、勾选、编辑和点击交互；
4. 后端根据查询效率、结果复用和使用频率设计合适的数据接口与形式，高内聚、低耦合、可扩展；
5. Good 与 Bad 分别观察**验收通过率**；整体验收完成率不按 Good/Bad 拆分；
6. 公共组件不满足时允许合理增强，"优先复用"不等于"不准修改公共组件"。

冻结实验题（`production-prompt.md`）对应的是其中一小块，且形态与第 2 条直接冲突：
它把"缺口量"这一个单元格做成详情入口，详情内容是固定 12 项汇总和固定三条趋势，
**没有**实现"任意单元格可下钻、沿剩余维度继续分析、详情内聚合展开/筛选/勾选/编辑"，
**没有**实现用户自选聚合维度，**没有**做后端按效率/复用/频率的接口设计，**也没有**落在
第 5 条要求的"验收通过率"口径上（实验观察的是分配达成率）。

└─ 业务模块：标注与验收分析

   │               表格缺口单元格变按钮；抽屉加缺口详情分支

### 3.2 从什么改成什么

| 位置 | 原来的情况 | 本次修改 | 修改后的作用 |
|---|---|---|---|
| `catalog.py` | 已有整体分配指标，无 Good/Bad 缺口口径 | 新增 good/bad 的 expected_allocated、allocation_shortfall、allocation_fulfillment_rate | 详情可按类别取数 |
| `repository.py` | 缺口为 Good/Bad 正差合并汇总 | 拆出 good/bad 各自的正差聚合 | 保持"局部超额不抵消"算法 |
| `TaskAnalysisTable.vue` | 缺口单元格是普通文本 | 改为 `shortfall-detail-button`，点击发出 `openMetricDetail` | 缺口数字成为详情入口 |
| `TaskMetricDetailDrawer.vue` | 详情为 Good/完成/通过三类 | 新增 `acceptance.allocation_shortfall` 分支（12 项汇总 + 3 条趋势 + 口径） | 缺口详情只展示分配口径，不读选项统计 |
| `useTaskMetricDetail.ts` | 详情总读问题选项 | 缺口指标跳过 `loadOptions` | 避免无关选项统计 |
| 键盘 | 无焦点管理 | 焦点进入、Tab/Shift+Tab 环绕、Escape 关闭、焦点回触发按钮 | 键盘可操作 |

方案本身实现质量良好且与冻结实验题一致，但**方案对象来自实验题而非原始诉求**，因此
方案是否"合理"不能替代"任务对象是否合法"的判断。

## 4. 独立实验事实（保留，不请求批准）

以下内容只证明冻结实验题自身的完成情况，作为独立 Harness 实验证据保留：

- **后端指标（`catalog.py` / `repository.py`）：** 新增
  `good/bad.acceptance.{expected_allocated, allocation_shortfall, allocation_fulfillment_rate}`；
  shortfall 沿用 `GREATEST(expect-actual, 0)` 先按员工日快照分 Good/Bad 取正差再汇总，
  不出现 `GREATEST(SUM(...))` 的抵消错误。
- **前端入口（`TaskAnalysisTable.vue`）：** 缺口单元格改为 `button`，带
  `aria-label="查看 {objectLabel} 验收分配缺口详情"`，点击 emit `openMetricDetail`。
- **详情抽屉（`TaskMetricDetailDrawer.vue`）：** 缺口分支展示整体/Good/Bad 的预期分配、
  实际分配、分配缺口、达成率共 12 项；ECharts 三条折线（整体/Good/Bad 按日缺口）；
  "口径与数据边界"分区；该分支隐藏问题标签—选项区。
- **键盘闭环：** 抽屉打开聚焦首个可聚焦元素，Tab/Shift+Tab 在抽屉内环绕，Escape 关闭，
  关闭后焦点回到触发按钮（`watch` 记录 `lastTriggerLabel`）。
- **验证证据（`verification-report.md`，执行者声明）：** 2026-08-11；Python 19 项、
  Vitest 32 项、Vue 类型/构建通过；真实 API 任务/日期/组/标注员/零分母逐级核对
  （低速跟随任务-20 Good 127 + Bad 46 = 整体 173）；真实 Edge 键盘事件。
- **明确没有做的：** 没有新增专用数据库表、平行查询系统、告警阈值、负责人、自动动作；
  没有读取问题选项统计；没有实现"任意单元格下钻""自选聚合维度""详情内聚合展开/筛选/
  勾选/编辑"。

**验证边界：** 以上验证与用户原始产品诉求无直接对应关系；只能回答冻结实验题
"缺口详情是否可用"。

## 5. 回到哪个需求问题

本切片停止后，应回到原始诉求本身，按用户真实选择重新规划：

1. **多维多选聚合与展开表**：用户可自选聚合维度（而非固定任务→日期→组→标注员）、
   再沿其他维度展开，维度关系不写死 —— 这需要前端表格/后端查询接口的通用化设计；
2. **任意合法单元格下钻**：每个合法统计数值单元格都是详情入口，在当前行范围内沿剩余

3. **详情多维交互**：详情内可复用聚合展开表格、统计卡片、图表，并支持筛选、勾选、
   编辑、点击；
4. **后端接口设计依据**：按查询效率、结果复用、使用频率设计接口与形式；
5. **Good/Bad 口径**：Good 与 Bad 分别观察**验收通过率**；整体验收完成率不按 Good/Bad 拆分。
