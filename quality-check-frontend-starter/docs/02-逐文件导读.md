# 02. 逐文件导读

## 根目录

### `package.json`

项目清单和命令入口。

- `dependencies`：浏览器运行需要的库；
- `devDependencies`：编译和类型检查需要的工具；
- `scripts`：`npm run dev/build/preview` 的实际命令。

### `vite.config.ts`

Vite 配置：

- `@` 映射到 `src/`；
- 开发端口固定为 5173；
- 可将 `/api` 代理到 FastAPI；
- `loadEnv` 读取环境变量。

### `.env.development`

开发环境开关：

```env
VITE_USE_MOCK=true
VITE_API_BASE_URL=/api/v1
```

修改后必须重启 Vite。

### `tsconfig*.json`

TypeScript 配置。

- `strict: true`：尽量在编译阶段发现错误；
- `paths`：支持 `@/shared/...`；
- `noUnusedLocals`：不允许留大量无用代码。

## 应用入口

### `src/main.ts`

启动顺序：

```text
createApp(App)
  → 安装 Pinia
  → 安装 Vue Router
  → mount('#app')
```

这里还引入全局 CSS 和 GridStack CSS。

### `src/App.vue`

根组件。只挂 `AppShell`，不写业务逻辑。

### `src/app/components/AppShell.vue`

平台统一壳层：

- 固定侧栏；
- 一级导航；
- 顶部页面标题；
- `<RouterView />` 页面出口。

### `src/app/router/index.ts`

路由表：

```text
/dashboard
/manual-qc/deliveries
```

以后新增验收中心：

```ts
{
  path: '/manual-qc/acceptance',
  component: AcceptancePage,
}
```

## 人工质检 feature

### `types/delivery.ts`

定义前端理解的一条交付记录：

```ts
DeliveryRow
DeliveryQuery
DeliveryUpdate
```

这应该对齐 FastAPI OpenAPI，而不是直接复制数据库表全部字段。

### `mocks/deliveries.ts`

本地演示数据。父任务包含日期子行，用于演示层级展开和父子选择。

### `api/deliveries.ts`

统一 API 门面。

页面永远调用：

```ts
getDeliveries()
updateDeliveryCell()
```

页面不关心当前是 Mock 还是真实后端。

### `pages/DeliveryWorkbenchPage.vue`

这个文件是“业务装配层”，负责：

- 声明人工质检列；
- 声明哪些列可编辑；
- 获取数据；
- 组合业务筛选；
- 调用共享 DataWorkbench；
- 打开 AnalysisBuilder；
- 将 ChartSpec 交给 DashboardStore。

不要把 TanStack Table 的底层状态复制到这里。

## 统一数据工作台

### `types/workbench.ts`

- `WorkbenchViewState`：要保存的表格状态；
- `SavedWorkbenchView`：个人视图；
- `ColumnEditorSpec`：列编辑器定义。

### `components/BaseCheckbox.vue`

封装普通、选中、半选三种状态。父子选择需要 `indeterminate`。

### `components/DataWorkbench.vue`

核心共享组件，内部使用 TanStack Table。

职责：

- 排序；
- 展开；
- 父子选择；
- 列显隐；
- 列顺序；
- 列宽；
- 行内编辑控件；
- 上下镜像横向滚动；
- 导出和恢复 ViewState。

它不调用人工质检 API。

### `composables/useWorkbenchViews.ts`

负责保存、更新、删除个人视图。当前存 localStorage，后续可以替换为 `/api/view-configs`，而页面调用方式保持稳定。

## 分析构建器

### `types/chart.ts`

定义 `ChartSpec`，也就是一张图的可持久化配置。

目前包含：

- 维度；
- 指标；
- 图表类型；
- 聚合后的数据；
- 筛选说明；
- 创建时间。

正式版本不应该长期保存聚合结果，而应保存 `QuerySpec + MetricSpec`，刷新时重新查询后端。

### `components/BaseEChart.vue`

ECharts 生命周期适配：

- mounted 时 init；
- option 变化时 setOption；
- 容器变化时 ResizeObserver resize；
- 卸载时 dispose。

### `components/AnalysisBuilder.vue`

演示：

```text
选维度 → 选指标 → 选图表 → 预览 → 添加到看板
```

## 可配置卡片看板

### `types/dashboard.ts`

定义：

- `DashboardCard`；
- `GridPosition`；
- KPI、图表、文本、表格卡片内容。

### `stores/dashboard.ts`

Pinia Store：

- 默认卡片；
- 新增图表卡片；
- 新增文本卡片；
- 复制、删除；
- 更新布局；
- 恢复默认；
- 自动持久化。

### `components/CardShell.vue`

统一卡片外壳：标题、描述、内容、复制和删除。

### `components/DashboardGrid.vue`

GridStack 和 Vue 的连接层：

- Vue 负责渲染卡片；
- GridStack 负责拖拽和缩放；
- change 事件转换成 `GridPosition`；
- 编辑态控制是否允许拖拽。

### `app/pages/DashboardPage.vue`

业务看板页面，负责工具栏和 DashboardGrid 装配。

## 本地持久化

### `shared/persistence/storage.ts`

localStorage 外面包一层：

```ts
{
  schemaVersion,
  savedAt,
  data
}
```

将来配置结构升级时，可根据 `schemaVersion` 做迁移，而不是直接解析旧 JSON 后崩溃。
