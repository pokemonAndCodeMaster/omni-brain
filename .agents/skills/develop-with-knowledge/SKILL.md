# 带知识开发

完成一条**最薄可运行纵切**：用户结果正确、既有组合不退化、真实环境有证据、长期知识有明确交接。不要把“查完所有背景”当作开始开发的前提。

## 1. 固定用户结果

先用普通语言明确：

- 谁在什么入口使用；
- 输入或操作是什么；
- 正常、边界和失败时分别看到什么；
- 哪项运行证据能证明有用。

不确定项若会改变业务语义、公共契约或副作用，停止实现并进入项目声明的完整知识准备/方案流程；不要用模型常识补全。

**完成标准：** 能用一段话描述用户怎样触发、看到什么、怎样判断通过。

## 2. 取得最低充分上下文

按以下顺序定向读取：

1. 当前项目的 `AGENTS.md`、当前接力页和组件地图；归档只在追溯特定理由时读取。
2. 项目声明的正式知识入口或产品视图，初始最多读取三篇会改变实现的页面；知识未覆盖时直接说明缺口，不递归通读原料。
3. 当前源码、Schema、配置和运行结果。精确实现以它们为准，知识用于业务意义、边界、设计理由和修改地图。

始终区分**来源身份**。若正式知识与当前工程属于不同仓库、提交或原型，不得合并成同一个“当前实现”；把知识当作业务/架构线索，再以本工程事实裁决行为。

在动代码前明确四项：已知业务语义、当前事实源、预计修改链、仍会改变行动的未知。没有新的未知会改变方案时停止继续查找。

**完成标准：** 已知当前行为由谁拥有、可复用能力在哪里、最小修改链和关键未知；每项结论都有直接落点。

## 3. 沿现有纵切找最小改动

沿真实用户动作追踪输入、转换、输出和状态，不机械凑齐技术层。先寻找已存在的指标、算法、接口、公共组件、配置和验证入口；已有能力足够时只接入消费链。

实现前执行一次**组合审计**：

- 新字段或动作与可选列、插件项、批量项、层级下钻叠加后，数量和请求上限是否仍成立；
- 旧保存配置、旧 Schema、默认值和迁移数据是否仍能加载；
- `null`、零、空集合、超过 100%、部分失败等既有边界是否保持语义；
- 共享能力的其他消费者是否被公共修改影响；
- 新测试是否在保护真实契约，而不是只证明当前实现自洽。

只修改实现用户结果所需的层。调整公共契约时使用当前工况要求的最低充分范围，不预留没有证据的容量。

**完成标准：** 变更范围能解释为一条必要纵切；组合审计中的每一项已验证、明确不适用或保留为阻塞。

## 4. 实现并保持边界

- 延续项目已有分层、命名、类型和依赖方向；不为两三个同职责字段新造抽象。
- 将数据转换放在已有边界，不在模板、页面或调用点临时拼动态字段。
- 复用公共能力，不复制排序、筛选、保存、重试或错误处理的旁路实现。
- 不顺手重构无关代码，不把目标设计或历史原型覆盖为当前事实。

**完成标准：** Diff 只包含必要实现、必要契约保护和必须同步的当前工程说明。

## 5. 用真实路径验证

使用项目已经声明的环境和命令；不要自行安装依赖、切换解释器或重建用户数据。

按风险递增验证：

1. 类型检查、编译和已有高价值回归；
2. 只为新增算法、边界或契约补聚焦测试；
3. 在项目真实数据库、API、CLI 或页面运行一个正常样例；
4. 运行至少一个会改变判断的边界/失败样例；
5. 涉及页面、持久化或外部副作用时，验证真实用户旅程，不用 jsdom、mock 或声明代替。

验证完整组合，不只验证新字段孤立存在。例如可固定五个选项时，要验证基础请求与五个选项同时存在；支持保存时，要验证旧配置与新列共存。

环境本身不可用时，记录失败位置、已完成证据和用户仍无法确认的结果；不得把评测者事后补跑写成生产会话自行完成。

**完成标准：** 新鲜证据覆盖用户结果、关键组合和相关边界；不能完成的真实路径被准确标为未验证。

## 6. 形成知识变化候选

交付时单列“知识变化候选”，至少说明：

- **来源身份：** 哪个仓库、版本或运行环境产生新事实；
- **变化事实：** 新增、修改或被推翻了什么；
- **规范落点：** 建议原位更新、创建新实现页，还是无需改知识；
- **保持边界：** 哪些业务规则、生产结论或目标设计没有因此改变；
- **证据：** 对应代码、Schema、命令或运行结果。

若正式知识尚未登记当前工程，优先提出独立来源记录和实现页，不把多个原型静默融合。除非用户明确授权发布，否则只提出候选，不直接修改正式知识。

**完成标准：** 每项稳定变化都有落点或明确的“不需更新”理由；未知和不同实现身份没有被抹平。

## 7. 交付

最终说明：

1. 用户现在能做什么、在哪里使用；
2. 修改了哪些责任边界以及为何是最小范围；
3. 实际运行了什么、结果如何；
4. 仍有哪些未验证或需要人类决定；
5. 知识变化候选是什么。

只有用户结果、组合边界、真实证据和知识交接都完成，才声明任务完成。用户无需维护内部状态时要明确说明。
