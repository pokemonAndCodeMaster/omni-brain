# “验收分配缺口详情”已完成开发工作：审查输入

> 本文件是审查模型可见的任务关系与工作交接，不是参考审查单或人工结论。候选不得读取 `eval/reference/`、历史审查候选、评分或用户后来给出的 R0 答案。

## 用户原始开发诉求

用户希望建设**完整、可复用的人工质检标注与验收结果统计和详情能力**：

- 前端提供公共的多维聚合与展开表格，不把维度关系写死；用户可以选择某个维度聚合，再沿其他维度展开；
- 每个合法统计数值单元格都可以成为详情入口，在当前行的数据范围内继续按剩余维度分析，而不是只允许某一个“缺口”指标下钻；
- 详情可以继续使用聚合展开表格，并结合可复用的统计卡片和图表完成多维呈现、筛选、勾选、编辑和点击交互；
- 后端需要根据查询效率、结果复用和使用频率设计合适的数据接口与形式，并具备高内聚、低耦合和可扩展的软件结构；
- Good 与 Bad 需要分别观察验收通过率；整体验收完成率不按 Good/Bad 拆分；
- 现有公共组件不能满足时允许合理增强，不能把“优先复用”误写成“不准修改公共组件”。

这是一项复杂前后端产品能力。用户没有批准把它优先拆成“只解释验收分配缺口的 Good/Bad 构成与趋势”。

## 实际交给执行模型的任务

候选还会收到同目录 `production-prompt.md`。该任务由 Harness 实验设计者后来构造，要求把现有“验收分配缺口量”单元格变为详情入口，只展示整体、Good、Bad 的预期/实际/缺口/达成率及按日趋势，并验证四级 Scope、零分母、键盘和真实运行。

它可以作为独立 Harness 实验题，但是否是上面原始诉求的合法需求切片，正是本次审查首先要判断的问题。没有找到用户批准该切片或方案的记录。
