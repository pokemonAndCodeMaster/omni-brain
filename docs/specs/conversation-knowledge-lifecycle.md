# 对话结论回收与续接协议

> **状态**：Provisional；用于让项目讨论形成可回溯、可验证的增量，而不把知识库变成聊天记录副本。  
> **关联**：[Blueprint](../blueprint.md)｜[产品方向讨论稿](../product-direction-discussion.md)｜[持续问题处理协议](continuous-problem-loop.md)

## 1. 目标

每轮讨论结束后，下一轮能够回答：之前在解决什么、当前结论是什么、为何如此判断、哪些仍待验证、有哪些案例或证据可继续使用。沉淀的是能改变后续判断或行动的结构化增量，不是会话全文的二次复制。

## 2. 分流规则

| 内容 | 归属 | 写入条件 |
|---|---|---|
| 原始对话、附件或逐字材料 | `knowledge/raw/conversations/` | 用户明确同意保存；新增后不可修改 |
| 产品取舍、候选架构、反例和开放问题 | `docs/product-direction-discussion.md` | 有明确理由、备选或待验证方式 |
| 已认可且有验证证据的目标、边界、成熟度、焦点或路线变化 | `docs/blueprint.md` | 明确认可或真实验证；不得仅凭讨论写入 |
| 日常痛点、失败信号与根因假设 | `docs/problems/` | 能描述场景、影响、问题层和下一步 |
| 可重复的真实任务与验收标准 | `docs/scenarios/`、`eval/` | 有输入、预期、失败表现和通过条件 |
| 稳定事实、规范、经验、代码地图 | `knowledge/` | 符合来源、状态、冲突检查和 taxonomy 约束 |
| 一次任务的临时上下文和草案 | 会话/任务投影 | 默认不持久化；反复有用后再升级 |

## 3. 回收节奏

1. **对话中**：识别候选，说明它是事实、推断、取舍、反例还是未决项。
2. **关键转折后**：输出简短沉淀候选，包括依据、成熟度、关联对象和建议去向。
3. **用户要求沉淀后**：保存允许保存的原料，并将候选分别更新到对应规范落点；避免同一结论复制到多处。
4. **任务/实验完成后**：补写结果和反例，决定结论是升级、维持 provisional、替代还是废弃。
5. **下一轮开始时**：先读 Blueprint；再按当前问题读取关联讨论、活跃案例、场景、评测结果和规范知识，而非重读全部历史会话。

## 4. 面向用户的回合收束与行动交接

结构化结论只有被用户看懂并知道怎样继续，才完成对话交接。非简单讨论与设计回复默认采用两部分；简单事实回答、即时状态和纯执行结果可省略。

### 4.1 本轮决定

只列真正改变当前理解或行动的内容，按需区分：

- 已确认；
- 暂定判断及成熟度；
- 已修正或排除；
- 仍未决。

不得把探索性发现包装成已确认结论，也不得重复正文全部内容。没有新结论时，应明确本轮只澄清了什么问题或获得了什么证据。

### 4.2 现在怎么继续

当继续推进需要用户选择、授权、材料或确认时，至少说明：

| 字段 | 要回答的问题 |
|---|---|
| 推荐行动 | 当前最建议走哪条路径，为什么 |
| 用户动作 | 用户需要回复什么、选择什么或提供什么；尽量给出可直接使用的表达 |
| Agent 动作 | 收到触发后 Agent 会执行哪些操作 |
| 预期产物 | 会新增/修改什么，用户最终得到什么 |
| 无动作影响 | 用户暂不行动时会停在哪里；无实际影响时也可说明 |
| 其他路径 | 只列真正有意义的 0—2 个替代选项及其差异 |

行动项必须有责任人、触发/输入、动作、产物和验收。禁止用“建议后续沉淀”“可以考虑更新”之类没有执行主体和触发结果的句子收尾。

如果无需用户行动，明确写明“你现在不需要提供额外信息；我将/已经……”，不要为了模板向用户制造选择题。

### 4.3 常用互动表达及结果

用户不需要记住固定命令，语义等价的自然语言同样有效。Agent 在当前情境首次提供这些选项时，应解释结果。

| 用户表达示例 | Agent 行为 | 结果与边界 |
|---|---|---|
| `只沉淀结论` | 分流更新讨论稿、场景、问题、工作台或日志 | 不保存逐字原始会话 |
| `沉淀本轮，包含原始对话` | 新增不可修改的 raw 原料，再分流结构化结论 | 同时保留原始证据；敏感内容仍需控制范围 |
| `作为问题记录` | 新建/更新 `docs/problems/`，记录场景、影响、假设、行动和验收 | 进入观察或实验，不自动改变 Blueprint |
| `更新操作规则` | 修改 `AGENTS.md`，详细机制写入对应协议 | 后续 Agent 默认受新规则约束 |
| `更新 Blueprint` | 核对成熟度、依据和影响后形成并执行或请求确认方向性变更 | 不绕过验证、人工审批和 change set 门槛 |
| `加入知识库` | 执行原料、草案、冲突、门禁、登记、日志和索引流程 | 形成可检索规范知识，不把未验证讨论冒充事实 |
| `先试用，不改文件` | 仅在当前连续对话中采用候选规则 | 可观察效果，但新会话不保证延续 |

### 4.4 长度与呈现

- 开头先给判断，正文围绕一个中心问题组织；
- 回合收束通常控制在 3—6 条，省略空字段；
- 只展示当前相关的互动选项，不重复完整术语表；
- 详细依据留在正文或链接中，结尾不再复制；
- 用户明确表示疲劳或困惑时，优先修复结果视图和行动交接，而不是继续增加解释。

## 5. 当前工作台与容量控制

`docs/now.md` 是项目的续接视图：它只显示当前目标、活跃线程、近期关键结论、开放问题和下一步链接，不能复制原文、完整讨论或规范内容。

初版容量上限：

- 最多 12 条活跃线程；
- 最多 10 条近期关键结论；
- 最多 12 条开放问题；
- 最多 10 条最近变化；
- 每项限制为一两句摘要加权威来源链接。

已解决、被替代或超出近期范围的事项从当前工作台移除，但保留在其问题记录、讨论稿、评测报告或知识卡的原位置。不得为“保留历史”在当前工作台另建长篇归档。

触发一次工作台整理/重构评审的条件包括：任何容量上限被突破、多个线程无法清楚归属到当前目标、连续两次需要大幅压缩才能续接，或用户主动要求。评审应决定合并、关闭、拆分或调整视图字段，并记录原因；不自动删除原始材料或规范结论。

## 6. 最小决策记录

每个影响产品方向的讨论增量尽量回答：

- 当前问题与任务背景；
- 当前结论及其成熟度；
- 依据、反例和被放弃的备选；
- 仍待验证的问题及验证方式；
- 对 Blueprint、案例、评测、知识或实现的影响；
- 可继续下钻的来源和关联对象。

## 7. 质量边界

- 不以“看起来有价值”为由自动创建知识卡；需区分稳定事实与讨论推断。
- 不以 Blueprint 代替讨论历史，也不以讨论历史掩盖 Blueprint 的当前状态。
- 不保存敏感或原始会话内容，除非用户明确同意；结构化结论只保留完成当前目的所需的最少信息。
- 任何结论被真实任务推翻时，保留其历史理由和替代链接，不静默覆盖。
