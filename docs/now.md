# 当前实验工作台

> 最近更新：2026-07-25。

## 当前状态

知识摄入已能在发布前隔离候选并形成局部业务—代码纵切。V8 前向 Trial 已改善知识区域、有效图表和当前 Python 纵切，但模型用一次超长输出批量读取材料后漏掉了关键设计内容。当前第九版状态是 `implemented_content_first_v9_awaiting_forward_test`；正式知识仍为空，也没有参考答案或业务评分点进入本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、Agent 覆盖声明、固定根入口、内容声明契约和结构门禁；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 第九版能否先形成来源主题地图，再逐篇或小批读取会改变知识地图的实质材料；
- 工具输出截断时能否停止 `read_full` 声明，避免把未读内容伪装成已覆盖；
- 初稿后能否发现“材料已提供但正文无落点”的主题并回到知识编织；
- 完整性判断能否按上级、主题全貌和用户焦点的原始问题范围进行；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。

## 下一动作

冻结第九版基线后，用完全相同的真实需求和来源运行前向 Trial。主要检查关键设计材料是否进入定向阅读、来源主题是否都有知识落点、领域层级和完整业务/数据/执行知识是否增长，同时确认 V8 已有的区域、图表和软件深度不回退。候选在通过人工内容审查前不发布、不升级能力状态。
