# 当前能力

> 最近更新：2026-08-02。

## 当前状态

本项目正在验证 M1“知识整理与摄入”。聚焦代码、宽范围基础整理和单模型增量融合均已有固定真实材料的内容证据；当前增量候选已准备好接受人工审查，但正式发布和跨模型稳定性尚未完成。

同一个 `ingest-knowledge` Skill 提供两条最低充分路线：

- **宽范围完整整理：** 固定材料 → 可完整阅读的材料单元 → 带必要细节和精确定位的发现 → 长期知识主题 → 发现到正文标题映射 → 产品视图与来源追溯；
- **聚焦代码或问题：** 明确问题 → 小批直接来源 → 规范知识 → 需要时在隔离环境真实运行。

用户只需从项目根目录提出自然语言请求，最后审查候选知识、产品视图和 `review.md`。后台状态仍只有 `.state/case.json` 与 `.state/source-manifest.jsonl`。

已有正式知识时，工作台会先冻结父版本文件指纹并把它原样复制到候选；本次只扫描新增材料。知识主题显式区分新增、原位更新和合并，审查页展示父版本到候选的实际差异。未计划的正文/视图修改和父知识删除会阻止发布准备。

- 完整整理已在一批固定真实材料上形成规范知识、产品视图和可追溯来源，并达到预定内容接受线；
- 模型手写来源路径曾出现错误，现改为从已校验来源、发现和正文落点自动生成追溯视图；
- 回归、Skill 校验和候选领域地图下的知识检查通过；
- 原始材料和正式 `knowledge/`、`config/knowledge-domains.yaml` 未修改。
- 父版本继承已用认证知识与后来材料完成命令级冒烟：候选除自动来源增量区段外与父版本一致，旧来源导航得到保留，未完成材料审阅时不能提前发布。
- 单模型增量 Trial 已完整审阅授权材料，形成带定位发现和长期主题，并对父知识完成新增与原位修改，没有删除父知识。
- 增量候选补齐交付管理、人员权限和统一数据工作台，并同步人工质检、验收、领域入口及两种产品视图；最终消费复核能够正确区分当前覆盖、父版本限制与生产未知。
- 候选知识结构检查与人工内容复核通过；正式 `knowledge/` 与领域配置仍未修改。

这些证据只证明当前真实切片有效。不能把一次内容通过表述为完整摄入、正式发布或跨领域泛化已经完成。

## 当前边界

- 读后发现、知识归属和正文表达仍由模型完成；工具只校验来源、顺序、一致性和可重建关系，不判断业务真伪；
- 逐文档审阅提高内容保真，也增加了命令与阅读成本，仍需在后续用例观察人工与模型负担；
- Python 包、模块、函数和方法细节在主题合并时仍可能被压缩；
- 缺少直接证据的 OBS、真实 Delta、生产状态和规则边界只能保留为未知；
- 候选领域配置必须随知识一起人工审查，不能自动修改正式分类；
- 增量新增、原位更新、父知识保留、冲突/未知保留和产品视图同步已在单模型切片验证；是否能跨模型稳定复现仍未知；
- 只读消费模型已能给出正确范围答案，但仍有读取范围偏大的现象；这是 M2 查询与上下文节制问题，不再扩建 M1 摄入流程；
- 正式查询、Web 界面和知识随代码变化自动演进尚未实现。

## 下一验证动作
