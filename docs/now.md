# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在验证精简知识摄入纵向能力。真实文档和代码工况都已经证明问题驱动、小批直接来源、规范正文、产品视图和隔离运行能够形成部分可用结果，但内容与证据链仍不完整，不能发布。

当前修正版继续使用“目标→读者问题→小批直接来源→规范知识”，并处理五类真实阻塞：同一摄入案写操作串行；多步验证脚本和完整运行输出能够冻结；非 Git 运行输入必须声明边界；Git 来源身份可直接进入来源记录；后到证据和代表性正常/边界例子必须先进入正文再登记。代码专项运行只在需要真实运行的问题中触发，普通文档摄入不被强制升级。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 小批候选能够降低无界阅读，但当前排序仍可能漏掉关键业务或代码来源；
- 目标覆盖仍由 Agent 语义判断，工具只能暴露问题与知识落点，不能替人判断领域知识是否完整；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 现场运行结果只能证明当前环境；没有日期锚定、生成方法和校验和时，不能视为固定评测基线；
- 完整摄入质量、跨领域复用、不同模型稳定性和人工审查负担仍需通过基础文档与代码工况继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一使用动作

最新代码全链路摄入结果仍未达到接受线。评测输入已经固定，下一步用相同业务请求验证来源提交、后到证据和正常/边界对象能否真正进入正文。代码达到最低接受线后，再重跑基础文档用例，确认共享 Skill 没有因代码优化退化。两个工况都满足阶段要求前不升级能力状态。
