# 正式知识可信问答包 v1

## 真实工况

用户已经拥有一套获批的人工质检与验收知识，但日常不会先理解知识库目录、摄入工作台或内部状态文件。用户只会在项目根提出自然语言问题，希望立即获得**正确、最低充分、可追溯**的答案，并知道哪些是历史、目标、当前事实、冲突或未知。

本用例同时覆盖四种高频工况：

1. 新同学建立业务全貌；
2. 判断某些产品能力是否已经在生产实现；
3. 面对互相冲突的数据结构时决定能否继续开发；
4. 为一个真实开发任务取得最低充分上下文。

## 固定输入

- Harness：`experiment/development-harness-v1@3cf55a9`；
- 正式知识：`/home/yyh/project/omni-brain-harness-quality-check-v1@900cf851865bcea9a959d795cf2c127f2c8094e1`；
- 知识根：`knowledge/index.md`；
- 模型不得读取本设计仓的 `eval/`、`knowledge/raw/`、历史 Trial 或参考答案；
- 普通问答不得创建工作区、YAML、报告或知识变更。

知识版本可以证明固定知识中的表达，不能自动证明生产部署、当前源码或新鲜运行结果。

| 场景 | 自然语言问题 | 验证重点 |
|---|---|---|
| Q1 学习全貌 | [人工质检验收的最短学习答案](prompts/q1-learning.md) | 领域位置、主线、对象边界、继续阅读 |
| Q2 现状与未知 | [哪些能力能确认已上线](prompts/q2-current-and-unknown.md) | 历史/目标/当前/生产未知不混写 |
| Q3 冲突决策 | [快照结构冲突能否直接改生产库](prompts/q3-conflict-decision.md) | 保留冲突、拒绝伪裁决、最小补证 |
| Q4 开发上下文 | [从 Ratio 预览走向正式分配](prompts/q4-development-context.md) | 最低充分规则、入口、验证与未知 |

## 用户最终得到什么

- 回答直接解决原问题，不先解释 Harness 或检索过程；
- 每个会改变行动的结论都能区分已确认、历史记录、目标设计、冲突和未知；
- 依据链接到具体规范知识，而不是只丢一个来源链接让用户自己读；
- 能回答时及时停止；单题默认只使用根/视图和最多三篇规范页，不无界翻库；
- 缺口只给最小责任人与直接证据，不用“大量补充资料”搪塞；
- Q4 输出足以让后续开发开始定向核验，但不预先生成大而全方案。

## 评测方法

固定内容题共 24 项，最低通过线为 21；所有关键题必须通过。内容与状态边界由人工审计，路径、文件写入、阅读范围和命令可从 Trial trace 复核。结构正确、引用很多或语气自信都不能替代内容通过。
