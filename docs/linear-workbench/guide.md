# 本地接续与文档联动

打开[个人工作台｜开始工作](https://linear.app/yyhpokemonmaster/document/abed03cc1da2)选择要推进的事；想读材料时，从[完整文档目录](https://linear.app/yyhpokemonmaster/document/736bd2d7d4bb)找原文，或从[已有知识与能力](https://linear.app/yyhpokemonmaster/document/43d261329834)选择阅读路线。资料可以直接浏览，不必先找到某条旧事项。

你可以用 Codex，或用具备 Linear 工具的 ChatGPT，接着同一件事讨论和执行。下一次工作的依据是事项当前正文、采用的方案和成果链接。想法怎样澄清、工作怎样拆分、如何审阅和改进技能，统一见[共同工作方法](https://linear.app/yyhpokemonmaster/document/cf8fc80d7255)；本页只说明入口和文档联动。

## 直接说你要做什么

在这台电脑任意项目目录的新 Codex 会话里，可以直接说：

| 你的诉求 | 示例 |
| --- | --- |
| 接着推进 | “继续个人工作台的视图设计，先读当前进展，再做下一步。” |
| 指定事项 | “继续 YYH-11，先读取事项和这次需要的文档全文。” |
| 随手记下想法 | “记录一个想法：我想每周看清哪些工作真正有进展。” |
| 只了解情况 | “看看工作台里的金铲铲资料，这次只阅读和讨论。” |
| 看交付结果 | “审阅这项工作，对照我原来要的效果，说明成果在哪里、哪些已经验证。” |

用户级入口会提示 Codex 使用 `personal-workbench` Skill。有明确匹配的事项就继续；没有编号时先搜索，不因换会话另建同名任务。涉及代码时再定位实际目标仓库，读取该仓规则和源码；工作台的维护仓不决定每项代码应改在哪里。

2026-09-12 已在另一个独立代码仓的新 Codex 会话中实测：不给编号和 Skill 名称，它仍能找到 YYH-12，读取事项及设计全文，并说明当前下一步；全程只读。另一个新会话回答普通 Python 问题时，没有读取工作台 Skill 或调用 Linear。这证明了新会话的入口与只读接续；此前的 Linear 读写和文档发布见[验证记录](https://linear.app/yyhpokemonmaster/document/fa3d0673f664)，本次只读测试未覆盖所有执行流程。后续非交互写回检查被工具审批策略拒绝，回读确认未保存；因此不能承诺任何启动方式都能无人确认地写回，YYH-11 继续记录这一边界。

## 每个入口的实际能力

| 入口 | 当前情况与使用条件 |
| --- | --- |
| 当前电脑的新 Codex 会话 | 官方 Linear MCP 已通过本人 OAuth 登录，用户级 Skill 已安装并经过上述正反例验证。接续时仍读取线上最新内容。 |
| 已有的 Codex 长会话 | 不保证自动重新读取更新后的入口。可以说“使用 $personal-workbench，重新读取当前说明再继续”；缺少 Linear 工具时需新开连接可用的会话。 |
| ChatGPT | 用户报告已在个人自定义指令中加入工作台入口；本轮尚未独立验证跨会话接续。具体会话必须具有 Linear 工具及账号访问，不能从本机 Codex 登录成功推断它已接通。 |
| 其他电脑或云端 Codex | 需要在当地安装入口并完成 Linear 授权，再用真实事项和文档验证。当前机器的配置不会自动复制过去。 |

连接不可用时，可以讨论用户提供的全文或带时间的快照，并完成不依赖线上状态的本地工作；必须说明哪些内容未读到、哪些结果未写回。恢复连接后先重新读取并合并。当前没有后台持续运行、自动巡视全部待办或定时同步；你的请求和本轮授权触发本轮工作。

## 文档怎样联动

每篇文档只确定一个主要维护位置。

- Git 已维护的规范知识或说明：在仓库修改原文，Linear 提供完整阅读副本。发布更新同一个文档，保留稳定链接。
- Linear 中持续讨论的需求、笔记和现有金铲铲资料：继续在原文档维护。本地保存阅读快照；下载不等于已经核实内容或收入正式知识。

需要发布时，在本地说：“同步个人工作台的 Git 文档到 Linear，检查线上是否有新修改，有冲突先给出差异。”Agent 读取发布清单、源文件和线上全文，合并需要保留的内容，生成本次修改，保存后重新读取确认。没有变化就跳过；保存超时先查询实际结果，避免重复创建。

如果两端都有修改，先保留线上新内容和差异，合并到本地原文后再发布。新增源文档须明确登记，不因此上传整个知识库、原始资料或环境配置。具体安装、发布、快照与检查命令只在代码仓的 `docs/linear-workbench/README.md` 维护，由 Agent 按当前版本执行。

## 事项怎样关联材料

在事项正文中放真实文档链接，并说明用途，例如“本轮采用的方案”“必要背景”“已有验证结果”。当前需要读的材料放前面，其他参考按需展开；Resources 可补快捷链接。长报告可以成为事项的关联文档，重要成果同时登记到独立阅读目录。

同一份长期知识可以被多个事项引用，保留它原来的维护位置，不复制全文，也不为了关联另一事项而改变文档归属。知识目录、代码仓和成果原文各自可以直接访问，事项负责解释本次工作怎样使用或改变了它们。

本地阅读快照和按需生成的上下文包便于跨会话携带材料，但只能说明本次取到了什么。它们不取代 Linear 当前记录，生成时间也不等于资料更新时间；继续行动前仍需读取线上当前事项和必要资料。
