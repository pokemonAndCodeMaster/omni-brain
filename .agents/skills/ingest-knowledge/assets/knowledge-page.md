# <标题>

<开头直接给出本页核心答案、适用范围和不能据此推出的内容。具体形式按读者需要选择，不必设置“先说结论”等固定标题。>

## <能体现本页主线的实质标题>

<按学习、任务、查询、机制理解或排障中的一个主要意图组织正文，不按来源顺序拼接摘要。标题本身应说明内容关系，避免“背景”“详细说明”“图怎么读”等空泛标题。>

<章节先用一至两句说明其在父章节中的作用、范围或核心判断。正文块使用 `**对象关系：task 是可执行的最小对象。**` 这种“语义路标：核心判断”开头，后面再写机制、证据、限制或例外；不要只加粗标签，也不要给每个换行机械套“概述/详情/结论”。仅引出列表或表格时可以只保留路标，由列表项名称或表头承担重点。>

<需要说明上下游或全貌位置时，使用标准 Markdown 链接并讲清上游提供什么、本页产出什么、下游怎样使用；不要为了套模板强行增加一节。>

## <可独立理解和维护的下一知识块>

<根据认知任务选择短段落、列表、表格或图。若使用图，图只回答一个主要问题；图前给出它支持的核心判断，邻近内容补充输入输出、条件、数据变化、异常、约束和边界，不复述图形。>

<从业务行为出发讲清对象、步骤、状态、规则或实现。改变结论的细节进入正文，帮助验证的细节放在结论附近，只供追溯的完整原料留在来源记录或附录；引用不能代替知识内化。>

<现实形态、证据边界或未知会影响使用时，用实质标题单独说明。只有多项结论需要按相同维度比较时才使用“结论 / 现实形态 / 直接来源 / 适用范围 / 冲突或未知”表格；单项内容使用短段落或列表。现实形态只能使用：当前实现、当前业务决定、目标设计、历史快照、开放问题。>
