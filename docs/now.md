# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在验证精简知识摄入纵向能力。代码工况已经达到当前接受线；基础文档同材料复跑仍遗漏领域全貌、完整数据状态、结论规则和公共能力，不能发布。

当前实现继续使用“目标→读者问题→小批直接来源→规范知识”。共享目标覆盖修订让模型建立了更多负责问题，并改善软件结构与数据库公共边界，但当前代码仍会吞没业务决定、目标设计和历史事实。继续追加 Skill 文字的收益已经不足，当前版本只保留为实验实现，不再直接复跑。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 小批候选能够降低无界阅读，但当前排序仍可能漏掉关键业务或代码来源；
- 目标覆盖仍由 Agent 语义判断；同材料复跑证明问句覆盖不能保证知识主题和证据角色完整；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 现场运行结果只能证明当前环境；没有日期锚定、生成方法和校验和时，不能视为固定评测基线；
- 完整摄入质量、跨领域复用、不同模型稳定性和人工审查负担仍需通过基础文档与代码工况继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一使用动作

下一步回到设计仓库讨论目标建模与知识规划组件：先确认用户工作流、后台信息结构、组件边界和技术选项，再决定是否修改本 Harness。此处不继续追加 Skill 文案或启动新的基础文档 Trial。
