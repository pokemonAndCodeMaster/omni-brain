# 对象存储（OBS）公共能力

## 先看结论

质检平台目标材料把 OBS（对象存储服务）列为跨模块基础能力，用户也确认它会被质检模块乃至数据团队共同使用。因此它应有一个公共规范落点；但固定代码提交中 `src/obs/` 只有占位文件，没有 `ObsManager` 或可验证客户端，当前不能编写具体 API、重试行为或运行保证。

## 公共和领域分别维护什么

```mermaid
flowchart LR
    C[OBS 公共能力\n连接、认证、基础读写、错误语义] --> U[人工质检使用契约]
    U --> D[领域语义\n对象路径、文件格式、批次、保留周期]
```

| 归属 | 应说明的内容 |
|---|---|
| 公共能力 | 客户端怎样取得、通用上传/下载/列举语义、认证配置、统一错误和维护责任 |
| 人工质检或验收 | 为什么使用 OBS、读写什么业务对象、路径怎样关联交付任务、失败会阻断哪一步 |

## 当前能确认到哪里

- 目标技术栈列出 OBS，并把未来的 `src/obs/ObsManager` 画在共享公共模块中。
- 固定代码没有该实现，当前验收原型也没有真实 OBS 调用链。
- 现有验收材料不足以确认验收直接读写哪些对象、对象路径规则、格式、版本和保留周期。

因此第 4 轮只建立这一缺口页。未来出现第一个真实 OBS 用例时，应同时补充公共接口证据和领域使用契约；不能为了让架构图看起来完整而虚构实现。
