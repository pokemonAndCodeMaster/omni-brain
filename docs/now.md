# 当前实验工作台

> 最近更新：2026-07-22。

## 当前状态

M1 已完成四轮 Luna 真实 Trial。第四轮能沿真实业务动作下钻 Python/SQL/测试，并分开当前实现、目标方案与历史做法，但仍没有补齐质量领域上层、人工质检完整模块与对象状态、公共能力和更深入的软件设计，内容为 12/24。当前第五版状态是 `implemented_content_first_v5_awaiting_forward_test`：用逐题实答把缺失暴露到消费面，并强化主题全貌、软件结构和公共能力处理；正式知识仍为空，也没有参考答案泄漏到本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、Agent 覆盖声明、固定根入口、内容声明契约和结构门禁；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 第五版能否让 Luna 主动补齐上级领域、主题全貌和公共能力，而不是只把验收焦点写深；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。

## 下一动作

把第五版内容工作流作为新的干净 Harness 基线，再用相同真实摄入需求启动 Luna 前向验证。主要检查逐题实答是否真的推动模型补齐上级领域、人工质检全貌、公共能力、软件结构与修改路径，同时保留第四轮已经改善的真实代码下钻；结构检查继续只作辅助诊断。候选在通过人工内容审查前不发布、不升级能力状态。
