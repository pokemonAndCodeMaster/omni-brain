# 本地快照 CSV 导入：代码变化到知识回写

## 用户工况

Quality Platform Lab 在既有只读分析与验收分配缺口能力之上，新增了一个本地 CSV 快照导入纵切。业务读者和开发者需要从原有人工质检知识入口理解：用户怎样预览和确认，CSV 数据怎样转成领域对象并写入 PostgreSQL，哪些字段可以更新、哪些人工状态必须保留，确认令牌和事务怎样阻止陈旧或部分写入，以及这项能力在什么条件下不再适用。

这不是重新摄入整个代码仓，也不是另写“本次更新摘要”。新事实应原位进入既有来源、系统、数据、软件、公共数据库能力和产品视图；已有 QPL 分析链、验收缺口语义和生产未知仍须保留。

## 最终用户结果

从现有知识入口，读者不打开全部源码也应能够：

1. 判断这是同一 QPL 系统的顺序演进，而不是新系统或早期 Ratio 原型的一部分；
2. 直接运行 `snapshot-import preview/apply`，理解输出、确认方式和失败语义；
3. 解释 CSV 11 列、四字段自然键、七个来源字段和三层 JSONB 数据怎样转换；
4. 解释整批校验、状态合并、令牌、锁、事务、UPSERT 和不变行保护怎样连接；
5. 定位 CLI、模型、Service、Repository、PGConnector 与快照表的修改入口；
6. 从规范知识获得真实 PostgreSQL 与回归结果，而不是只看到“测试通过”的来源链接；
7. 区分本地低频导入、完整来源文件和未来 staging/批次系统的适用边界；
8. 继续从领域视图、学习旅程和系统页进入该能力，不丢失既有分析功能。

## 不能做错的边界

- 不把本地实验导入写成生产数据接入、通用 ETL、上传页面或人工质检生产流程；
- 不把固定验证中的日期锚定 SQL写成产品能力；
- 不声称 CSV 可以局部补丁式更新任意 JSONB；
- 不声称所有旧问题选项都会保留：已有同名 Good、Bad 和 CSV 内同名选项只保留 `conclusion/exec_status`，CSV 仍表示完整来源结构；
- 不删除、压缩或覆盖父知识中的只读分析、分配缺口、Ratio 原型、历史和生产未知；
- 不为了证明安全而创建模型不可见的隐藏实现或新的 staging 表。

## 评测方式

候选模型只看到自然语言任务、固定父知识、固定代码来源和 Harness，不看到强参考、内容问题或其他 Trial。独立审计同时检查最终内容、候选隔离、父知识保持、运行证据内化和过程成本。结构检查或 `publish_ready` 不能替代内容通过。
