# Agent Console v0 Evolution Trial 001

## 结论

线性进化的真实模型路径已经完整跑通：从 Seed 执行、独立 Judge、证据驱动的 Harness 修改、候选 commit、基于候选 revision 的同题干净重跑，到新的 Judge 与 best 选择，全部能在网页时间线中恢复并回到三个独立 Run。

候选综合分从 `98.0` 到 `98.5`，因此按 v0 的简单规则在本实验内成为 best；它没有合入 `release/harness`，也不应仅凭 0.5 分差异自动晋升。

## 迭代发生了什么

1. Seed 正确列出八项能力，但 Judge 指出“仅实现”分类有轻微语义重叠，并为精确行号重复读取一次 `harness.yaml`；
2. Optimizer 在独立 worktree 修改 `AGENTS.md`，要求使用互斥状态标题、保留原始 adoption，并一次带行号读取；同时增加一条契约测试；
3. 定向 24 项和完整 91 项 Release 测试通过，候选提交为 `73d23ab`；
4. 从 `73d23ab` 建新的干净 worktree 同题重跑，任务完成保持 `99`，执行过程从 `97` 变为 `98`；
5. 控制器记录 `+0.5` 并在本实验内选择候选，但不修改 Release 分支。

## 人工审计

这次结果同时暴露了 v0 的重要边界：单 Judge 的 0.5 分差可能是模型波动；候选把一个很窄的“列举能力状态”措辞和一次读取偏好写入了全局 `AGENTS.md`，存在为单题优化的风险。虽然修改有通用解释且 91 项测试通过，它仍需要换问法/换模型反证并由人判断是否值得增加全局规则负担。

因此，“实验内采用”和“晋升 Release”是两个动作。工作台已经完成前者的可视化与审计，后者仍保持显式人工门禁。
