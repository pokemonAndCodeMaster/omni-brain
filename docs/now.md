# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在验证精简后的知识摄入纵向能力：把用户授权材料的全量版本基线放到后台，围绕一个读者问题取得少量直接来源，立即形成规范知识和产品视图；需要时在临时 Git worktree 运行来源项目。正式知识库当前为空；用户批准前不得发布候选。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 小批候选能够降低无界阅读，但当前排序仍可能漏掉关键业务或代码来源；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 完整摄入质量、隔离运行、跨领域复用、不同模型稳定性和人工审查负担仍需通过 K0 与 E1 继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一使用动作

先用 K0 文档材料验证“问题 → 小批直接来源 → 规范知识 → 缺口收尾”，再用 E1 代码材料验证动态源码链和隔离 API/SQL/页面运行。只有内容质量、真实复现和过程成本同时改善，才考虑替换 RC1。
