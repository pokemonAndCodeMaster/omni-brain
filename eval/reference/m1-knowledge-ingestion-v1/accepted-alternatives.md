# 可接受替代方案

候选不需要与参考成果逐文件一致。只要保持核心定义只有一个维护位置、来源与信息性质清楚、关键细节不丢失、浏览路径可用且发布前经过人工确认，下列差异默认允许：

- 将生命周期拆成一页或两页；
- 将采样配额与任务选择合写或分别成页；
- 将验收结论与通过/打回执行放在同一页面的不同知识块，或拆成相互链接的页面；
- 将过程监控、结果分析和返工跟踪合在生命周期页，或作为独立主题页；但必须让读者能从分配继续走到返工或交付判断；
- 使用不同但清晰的中文文件名和阅读顺序；
- 使用不同的图表类型、布局和配色，只要能正确呈现层级、流程、算法或状态，并有完整文字说明；
- 不要求每个软件页面机械凑齐全部 4+1 视图；允许按问题选择业务流程、模块图、类图、时序、数据流、部署图、代码地图或真实代码走读，但必须让读者从业务动作追到实际 Python 结构和运行过程；
- 可以把系统跨层架构与 Python 软件结构合写或拆写，只要当前代码、目标设计和历史实现不会混在同一张“现状架构图”中；
- 使用其他有界阅读策略，只要没有泄漏、无界遍历或遗漏关键来源族。

改变业务定义、静默解决来源冲突、混淆信息性质、证据边界或公共能力归属不属于自由差异，必须有更强证据并经用户确认。
