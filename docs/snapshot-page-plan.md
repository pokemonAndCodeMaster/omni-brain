> 当前实现和既有页面说明保留在本文。V2 技术方案已经确认，且“任务级查询与指标目录”
> 已完成第一切片；后续以

## 页面目标

这一页不是把所有数字平铺出来，而是按使用者的判断顺序回答四组问题：

1. **标注产出了多少，结果是什么；**
2. **验收分得是否足够、是否覆盖完整；**
3. **已经分配的验收是否按时完成；**
4. **完成后的通过与打回分布在哪里，下一步应查谁、哪个任务或哪个选项。**

全页共享日期、项目、标注任务、组和员工筛选。项目当前为 `园区`、`城区/高速`；
`scene_name` 在界面中统一称为“标注任务”，同名任务表示同一批次。

## 信息顺序

### 一、业务总览

**用途：** 先判断总体规模和主要异常，再决定下钻方向。

| 内容 | 推荐呈现 | 点击后的动作 |
|---|---|---|
| 标注提交、Good、Bad | 指标卡 + Good/Bad 堆叠柱图 | 按项目或标注任务筛选明细 |
| 验收分配、完成、通过、打回 | 指标卡 + 并列柱图 | 按项目或标注任务筛选明细 |
| 完成率、通过率 | 指标卡中的比率说明 | 进入对应任务或项目 |

当前页面已实现三张可编辑总览卡：标注产出与质量构成、验收分配与完成、
验收通过与打回。每张卡同时展示选定周期全量与项目拆分，可修改文字、配色、
字号、内容密度和跳转目标，也可拖动、缩放并保存。

### 二、标注分析

**用途：** 回答“做了多少”和“结果分布如何”，先看任务，再在同任务内比较组和人。

| 分析问题 | 推荐图表 | 配套明细 |
|---|---|---|
| 每天不同项目、任务的标注量 | 日期趋势图，可切换项目/任务 | 日期—项目—任务汇总表 |
| 同一任务下不同组、人的标注量 | 横向条形图或排名表 | 任务—组—员工表 |
| 不同任务的 Good/Bad 分布 | 100% 堆叠柱图 + 实际数量 | 任务—Good/Bad 表 |
| Bad 中不同问题和选项分布 | 问题标签到选项的可展开条形图 | 任务—问题标签—选项表 |

固定标注图已用堆叠柱展示 Good、Top Bad 选项和其余 Bad，并用右轴折线展示
Good/Bad 占比；右侧同时给出 Bad 问题排行。自定义统计卡片支持日期、项目、
任务、组、员工、Good/Bad、问题标签和“问题标签/选项”等分组维度。现有数据
没有有效工作时长和统一难度系数，
因此只能比较产出量，**不能把产出量直接命名为标效**。

### 三、验收分配

**用途：** 回答“分得够不够、是否覆盖任务中的组、人、Good/Bad 和 Bad 选项”。

| 分析问题 | 推荐图表 | 判断依据 |
|---|---|---|
| 每天各任务分配多少 | 日期 × 任务柱图 | 实际分配量 |
| 各组、各员工是否被覆盖 | 任务 × 组/员工覆盖矩阵 | 是否存在零分配单元 |
| Good/Bad 和各 Bad 选项是否覆盖 | 堆叠柱图或覆盖矩阵 | 实际分配与标注构成 |
| 分配是否足够、相对均匀 | 预期/实际对照表 | `expect_alloc`、`actual_alloc` 与业务阈值 |

当前快照已保存预期和实际分配量，也能按任务、组、员工和结果层级统计。
“足够”和“均匀”仍需要业务方确认配额规则与容忍阈值，页面暂不替业务做结论。

### 四、验收完成

**用途：** 回答“已分配的任务做完了多少、剩在哪里”。

| 分析问题 | 推荐图表 | 点击后的动作 |
|---|---|---|
| 每日整体完成情况 | 分配/完成趋势图 | 筛选当天明细 |
| 哪些任务、组未完成 | 完成率条形图 + 未完成量 | 下钻到任务、组和员工 |
| 积压是否跨天 | 日期趋势 + 积压表 | 查看连续未完成对象 |

完成率统一采用 `actual_complete / actual_alloc`；固定图和自定义组合图均把数量
放在左轴、比率放在右轴，并可切换任务或按天趋势，避免不同量纲互相压扁。

### 五、验收结论

**用途：** 回答“通过与打回发生在哪里，以及问题是否集中”。

| 分析问题 | 推荐图表 | 下钻顺序 |
|---|---|---|
| 每日通过和打回 | 100% 堆叠柱图 + 实际数量 | 日期 → 项目 → 任务 |
| 哪个组或员工打回集中 | 同任务内的组/员工条形图 | 任务 → 组 → 员工 |
| Good/Bad 哪一类更易打回 | Good/Bad 对比图 | 结果类型 → 问题标签 |
| 哪些 Bad 选项更易打回 | 问题标签/选项条形图 | 问题标签 → 选项 |

通过率统一采用 `actual_pass / actual_complete`。固定图已展示通过/打回数量与通过率；
明细表支持完成率、通过率范围筛选和升降序。问题标签—选项的专用可展开明细仍是
下一切片。

## 统一交互

- 总览卡片点击后跳到对应固定统计；自定义卡片按日期、项目、标注任务、组或员工绘制时可以点击，
  页面会同步筛选并跳到逐级明细。
- 明细表按“日期 → 项目 → 标注任务 → 组 → 员工”展开；列头负责排序、筛选、
  调宽、显隐和顺序。
- 自定义卡片可以修改标题、说明、数据源、分组、指标、筛选条件、图形、图例、
  字号、排序和 Top N，也可以拖动、缩放、删除和刷新；柱线组合图适合同时表达
  分配/完成数量和完成率，或通过/打回数量和通过率。
- 顶部筛选统一定义全页数据范围；表头筛选默认只影响明细。用户点击“应用到全页”
  后，只转换日期或单值维度等可无损条件；数值比率等聚合筛选继续留在明细并提示原因。
- 保存的是卡片定义与布局，不是旧统计值。重开页面后自动读取最新快照再计算。

## 实现顺序

1. **已完成：** 项目拆分总览、总览跳转、任务/日期固定图、Bad 问题排行、四级明细、
   数值筛选与倒排、自定义双轴卡片、拖动缩放和两类卡片持久化。
2. **下一切片：** 标注任务—组—员工产出视图，以及任务—Good/Bad—问题标签—选项可展开明细。
3. **随后：** 验收覆盖矩阵与预期/实际配额对照。
4. **最后：** 完成积压和通过/打回的专用分析页签；业务阈值确认后再加入风险提示。
