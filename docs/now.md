# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在修正精简知识摄入纵向能力。首轮真实材料实验已经证明“小批直接来源、边读边写、候选区审查”能明显减少机械操作，并能区分当前事实、目标设计和历史做法；但模型把完整摄入目标缩成两个局部问题，最终知识不够完整，不能发布。

当前修正版要求先把用户最终结果映射到读者问题，再逐题取得少量来源和形成知识；证据登记后可以独立停止继续选源，不再为了关闭候选重新读取材料。正式知识库仍为空，用户批准前不得发布候选。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 小批候选能够降低无界阅读，但当前排序仍可能漏掉关键业务或代码来源；
- 目标覆盖仍由 Agent 语义判断，工具只能暴露问题与知识落点，不能替人判断领域知识是否完整；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 完整摄入质量、隔离运行、跨领域复用、不同模型稳定性和人工审查负担仍需通过 K0 与 E1 继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一使用动作

先用同一固定文档切片重放修正版，验证它能保留低过程成本，同时形成上位定位、完整流程、数据与状态、规则算法、系统实现和未知边界。内容明显改善后，再进入代码材料的动态源码链和隔离 API/SQL/页面运行；在此之前不升级能力状态。
