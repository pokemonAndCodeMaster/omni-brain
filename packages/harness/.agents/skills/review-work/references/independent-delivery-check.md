# 独立交付复核

本协议供一个**没有参与施工的新上下文**检查复杂软件候选是否真的满足批准条件。它关注用户结果和
内容事实，不评分提示词、不重复开发者的测试清单，也不替代人的最终验收。

## 输入

调用者必须给出：

- 原始任务和批准文件在修改前版本中的路径、Git commit；
- 候选工作树、Diff 基线和候选 commit 或工作树状态；
- 项目声明的真实运行入口与安全命令；
- 本次批准关闭条件；
- 可以复用的服务及其明确进程所有者。

缺少批准身份、候选身份或真实入口时返回 `not_proven`，不要从开发者总结、历史 Trial、同级仓库或
评分文件猜答案。

## 复核顺序

1. 从修改前 commit 读取批准条件；不要把候选 `review.md` 中开发者新写的完成状态当作批准事实。
2. 用 Diff 和当前源码定位每项能力的真实 owner、入口、状态变化和下游消费者。只读取能改变判断的
   文件，不重新通读整个项目。
3. 对每个强范围结果选择最可能推翻它的代表反例：非默认分支、第二层或不同顺序、筛选后的下游、
   重叠范围、另一个消费者、空值、失败或首次进入。反例来自批准语义和当前结构，不使用评测答案。
4. 从全新的用户入口亲自运行关键动作，观察业务结果；控件存在、请求 200、canvas 存在、文件非空、
   测试全绿或开发者曾运行过脚本，都不能代替真实后果。
5. 对筛选、展开、选择或范围切换，至少追踪一个承诺的下游消费者；对结构化产物，用正式消费者或
   成熟解析库核对字段、类型、代表值与重叠/空值；对公共复用，验证两个消费者共享同一 owner 且都
   能完成承诺动作。
6. 检查浏览器/服务错误、依赖审计、进程与临时数据副作用。只复用或停止调用者明确拥有的进程，
   禁止 `pkill -f`、模糊进程名、重置固定数据或修改受跟踪配置来迁就验证环境。

## 输出

先给总体结果 `pass / fail / not_proven`：

- `pass`：每项必需关闭条件都有真实业务后果证据，且没有会推翻完成结论的失败；
- `fail`：至少一项必需能力未实现、结果错误、越界或出现相邻回归；
- `not_proven`：能力可能存在，但当前身份、环境或证据不足以判断。

随后只报告会改变接受结论的内容：

| 关闭条件 | 结果 | 亲自执行的动作 | 观察结果与证据 | 需要怎样处理 |
|---|---|---|---|---|

最后列出实际读取的批准身份、候选身份、运行命令和产生的证据。不要编辑候选代码或 `review.md`；
把发现返回给开发者，由其修复或把未完成边界写入同一审查单。
