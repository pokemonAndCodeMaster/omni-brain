# 生产任务

人工质检验收负责人已经能在“标注与验收快照”页的任务表看到“验收分配缺口量”，
也能按任务 → 日期 → 组 → 标注员下钻，但这个数字还不能解释：缺口主要来自 Good
还是 Bad、计划和实际分别是多少、哪些日期反复出现。

请把现有缺口单元格改成详情入口。点击后，在当前任务或下钻对象的范围内展示：

- 整体、Good、Bad 的预期验收分配、实际验收分配、分配缺口和分配达成率；
- 整体、Good、Bad 三条按日缺口趋势；
- 用户理解这些数字所必需的口径和数据边界。

必须保持现有“先在员工日快照内分别保留 Good/Bad 正缺口，再向上汇总”的算法，
不能让局部超额抵消其他位置的缺口。问题选项目前没有预期配额，不要推断问题选项级
缺口，也不要为了本详情读取无关的选项统计。

请优先复用当前受控分析 API、指标详情抽屉、ECharts、四级 Scope 和公共表格能力。
不要新增专用数据库表、平行查询系统、告警阈值、负责人或自动动作。页面需要能被键盘
正常操作。

最终请用固定 PostgreSQL、真实 HTTP 和真实页面分别点击任务、日期、组、标注员以及
零分母对象完成核对，并运行项目全量回归。只报告本轮亲自观察到的证据；同时说明这次
代码变化应怎样更新长期知识，但不要直接发布知识。
