# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在验证知识摄入纵向能力。聚焦代码工况已经达到当前接受线；新的宽范围完整整理路线已实现并通过确定性测试与真实基础文档材料地图检查，但尚未经过内容 Trial，不能发布。

当前同一个 `ingest-knowledge` Skill 提供两条最低充分路线：宽范围完整整理使用“用户承诺 → 客观材料组 → 读后发现 → 知识目录复核 → 规范知识与产品视图”；聚焦代码或问题继续使用“具体读者问题 → 小批直接来源 → 规范知识 → 真实运行”。完整路线不再由文件名预判当前、历史或目标，也不维护多个活动小批。

后台状态仍只有 `.state/case.json` 与 `.state/source-manifest.jsonl`。单一游标公开当前材料组或知识主题、可打开路径和下一动作；重复 `next`、读后发现、材料登记与主题登记具有幂等恢复语义。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 完整整理的材料组按路径、重复、链接、代码依赖和容量边界生成；分组可重建，但相关性与事实身份仍需模型读后判断；
- 当前 12 文件/约 100 KB 的材料组容量只在首个真实材料包检查过，不是跨领域最优常量；
- 读后发现、知识目录和八个理解角度仍由 Agent 语义完成；工具能暴露漏项，不能替代内容判断；
- 聚焦模式的小批候选能够降低无界阅读，但排序仍可能漏掉关键业务或代码来源；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 现场运行结果只能证明当前环境；没有日期锚定、生成方法和校验和时，不能视为固定评测基线；
- 完整摄入质量、跨领域复用、不同模型稳定性和人工审查负担仍需通过基础文档与代码工况继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一验证动作

冻结当前候选提交后，按照设计仓库登记的固定输入、原始自然语言请求和实验模型，只运行一次基础文档内容 Trial。生产模型不得读取认证参考和既有审计；通过标准继续由设计仓库的实验总账管理。内容 Trial 前不再扩建组件。
