# 当前能力

> 最近更新：2026-08-01。

## 当前状态

本项目正在验证精简知识摄入纵向能力。代码工况已经达到当前接受线，但同一 Harness 的基础文档回归仍遗漏领域全貌、软件结构、公共能力和完整算法，不能发布。

当前修正版继续使用“目标→读者问题→小批直接来源→规范知识”。本轮只强化共享的目标覆盖责任：领域或模块摄入必须保留整体位置与全貌；用户承诺和适用观察角度必须由问题负责或有依据地排除；材料中新发现且会改变理解的算法、数据契约、软件结构和公共能力必须形成知识落点。代码专项运行仍只在需要真实运行的问题中触发，普通文档摄入不被强制升级。

## 使用结果

一次知识摄入应交付：

- 能从上级定位逐层下钻到用户焦点的规范知识；
- 面向浏览和实际任务的两种产品视图；
- 当前事实、目标设计、历史做法、冲突和未知的明确边界；
- 可回到直接来源和真实运行的证据链；
- 一个集中展示候选内容、开放问题和发布选择的人工审查入口。

用户只审查候选知识、产品视图和一份 `review.md`。机器来源基线和问题状态在 `.state/` 后台维护，不再要求 Agent 给全部文件逐项分类。

## 当前边界

- 小批候选能够降低无界阅读，但当前排序仍可能漏掉关键业务或代码来源；
- 目标覆盖仍由 Agent 语义判断；本轮文本修订能否让中等模型稳定保留整体目标，尚待同材料复跑；
- 结构检查不判断业务事实是否正确、范围是否完整；
- 只有直接证据支持的部分才能写成当前事实；
- 现场运行结果只能证明当前环境；没有日期锚定、生成方法和校验和时，不能视为固定评测基线；
- 完整摄入质量、跨领域复用、不同模型稳定性和人工审查负担仍需通过基础文档与代码工况继续验证；
- 正式查询引擎、Web 界面和知识随代码变化自动演进尚未实现。

## 下一使用动作

下一步使用同一批冻结文档、同一自然语言请求和相同模型复跑基础文档摄入，只观察完整目标是否真正变成规范知识与产品视图。若仍明显不足，停止继续堆叠 Skill 文字，回到目标建模与知识规划组件。代码与文档两个工况都满足阶段要求前不升级能力状态。
