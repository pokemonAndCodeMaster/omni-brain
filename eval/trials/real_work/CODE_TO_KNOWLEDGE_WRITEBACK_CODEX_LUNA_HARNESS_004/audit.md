# 代码变化回写第四轮 Luna 审计

## 当前结论

第四轮解决了第三轮最关键的两类遗漏：模型完整保留了 18 个快照顶层字段和 13 个嵌套指标字段，并在任何现场重跑之前找到、核对和复用了固定 commit 自带的验证报告。候选达到工作台的 `publish_ready`，结构检查通过，正式知识与代码来源均未修改。

但“工作台可发布”仍不能替代内容认证。按 24 个固定读者问题独立审查，本轮为 **22/24**，关键题 C13 未通过，因此暂不晋升为 `verified@quality-check-code-writeback-slice`。剩余问题都指向同一个内容矛盾：**来源读过或被检索到，不等于决定理解的细节已经进入规范正文。**

## 本轮使用的 Harness 与实际收益

模型使用 `c9bca1a` 的 `ingest-knowledge`。该版本增加了固定验证报告优先、Python 契约字段冻结与检查、已登记证据复用、导航错误提示和低成本语义检查。

这些改动产生了可观察收益：

- `docs/verification-report.md` 在系统身份阶段即被识别，模型没有再创建 worktree、clone 或尝试重跑数据库、API 和浏览器；
- `SnapshotRowOut`、`MetricState` 等契约经 `contract-inspect` 冻结，18 个顶层字段和 13 个嵌套字段完整进入数据页；
- 代码与验证报告的 “10+5”/“9+5” 差异没有被静默覆盖，而是以当前源码为事实并保留证据冲突；
- “上面四项”与实际五项的陈旧文案被语义检查发现并修正；
- 候选独立维护 QPL 来源页、系统页和软件页，业务数据与采样规则仍原位进入父知识，未形成按批次堆叠的增量附录。

第四轮仍有 59 次命令和 14 次非零退出。运行选择已经显著改善，但 `record` 对当前 packet、候选关闭和导航责任的交互仍让模型多次试错。该成本问题低于内容缺失的优先级，本轮没有为了减少命令数继续扩建控制面。

## 模型实际过程

1. 正确进入 `writeback`，读取正式知识入口后把固定代码判定为独立 `new_system`。
2. 从固定验证报告、快照 Schema、迁移、Catalog、Repository、Service、Router 和 Vue 任务树分批取证。
3. 对完整 Python 数据契约运行字段冻结；工作台在字段未全部进入知识时阻止问题通过。
4. 新建来源、系统和软件结构三个规范落点，原位修改数据、采样、未知、根入口、领域/旅程视图和导航日志。
5. 发现验证报告“9+5”和当前源码“10+5”不一致，按固定源码保留 10+5，并把报告表述留作待复核证据差异。
6. 没有新增现场运行；以固定 report 作为当前 commit 的验证证据。最终候选为 3 新增、9 修改、0 删除，236 行增加、10 行删除。
7. 工作台审查和知识结构检查通过，候选停在隔离工作区等待人工决定。

## 内容质量

### 已经达到的结果

- **数据契约完整：** 最小粒度、6 个快照过滤字段、18 个顶层字段、13 个 `MetricState` 字段、问题标签→选项→指标的 JSONB 层级都可直接回答。
- **算法语义可靠：** 预期/实际量、达成率、覆盖率、零分母、原子分类缺口和 Ratio 规划期互补的先后关系均进入正文；超额不能跨类别、日期、组或人员抵消。
- **系统边界清楚：** QPL 是固定 commit 的独立本地实验，不与早期 Ratio 原型合并，也不冒充生产、外部分配或完整执行闭环。
- **跨层结构可用于修改：** Router、Schema、Service、Catalog、Repository、Vue feature、任务树、详情和 shared workbench/dashboard 的责任及常见修改入口已经成页。
- **知识融合安全：** 父知识 0 删除，根入口、领域视图、学习旅程、系统和来源导航均同步可达；候选与正式知识隔离。

### 尚未达到的结果

1. **C13：前端行转换责任缺失。** 软件页说明了 `useTaskAnalysisTree`、`TaskAnalysisTable` 和 `DataWorkbench`，但没有明确写出 API `AnalysisRow` 怎样经 `utils.ts` 映射为任务树行、字段/层级信息在哪里归一化。这使开发者仍需自行发现关键转换入口。
2. **C15：固定验证结果内化不足。** 来源页说明报告覆盖 PostgreSQL、API、Vue 测试和真实 Edge，也记录了 3024 行、18 字段等数据范围；但没有保留代表性运行结果，例如 17 项 Python、30 项 Vue、24→14→3→3 四级下钻、真实 API/Edge 结果及 14/15 指标边界。读者知道“验过”，仍不足以判断“验到了什么程度”。
3. `review.md` 把“本案没有新增现场运行”写成“尚无真实运行证据”，并称当前没有冲突；这与已采用固定报告、正文保留 9+5/10+5 冲突不一致。它不影响规范正文，但会误导人工审查。

## 本轮后的最小 Harness 修正

评测后已在 Harness commit `ebd696c` 完成通用修正：

1. `ingest-knowledge` 要求在关闭软件问题候选前回到原始读者问题逐项核对；候选中存在 `types`、`utils`、`mapper`、`adapter` 等直接转换入口时，至少读取并解释一项，或说明为何不影响答案。
2. 固定验证报告被采用时，正文必须保留改变读者判断的覆盖范围和代表性结果，不能只写“测试通过”。
3. `review.md` 现在区分固定来源验证记录与本案现场隔离运行，并明确没有新增运行不等于没有运行证据。
4. 候选正文长期保留的未知/冲突不再被审查页错误概括成“没有冲突”。

完整 Harness 回归、Skill 结构验证、知识结构检查和 `git diff --check` 均通过。由于修正发生在第四轮之后，它需要后续同类或相邻真实切片反证；本轮不把未重放的改动虚报为已验证。
