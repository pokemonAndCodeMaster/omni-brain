## 逐层内容地图

不能默认用户焦点就是顶级领域。每层写清需要讲到的深度；确实不存在某层时说明理由。

| 层次 | 本轮主题 | 读者必须理解什么 | 展开深度 | 候选直接来源 |
|---|---|---|---|---|
| 上级定位 | | 所属领域为什么存在、与同级能力怎样分工；若确为根领域，依据是什么 | 定位，不展开相邻主题内部 | |
| 主题全貌 | | 端到端流程、角色、对象、模块和上下游 | 足以画出整体地图 | |
| 用户焦点 | | 业务、数据、软件、规则/算法和工程细节 | 本轮最深 | |

## 主题全貌切面

不能用一张流程图代替主题全貌。每个切面都应有规范落点、明确未知或确实不适用的理由。

| 切面 | 必须讲清什么 | 规范落点/未知 |
|---|---|---|
| 生命周期 | 从触发到真实完成、并行、异常、返工和下游去向 | |
| 角色与职责 | 谁发起、执行、审核、决策、消费结果 | |
| 核心对象与状态 | 对象、标识、关系、状态轴和关键口径 | |
| 平台/业务模块 | 按完整生命周期列出主要能力或工作台模块、职责、输入输出和交接；模块不是角色、对象，也不是 API/Service 等代码层名 | |
| 上游、下游与同级能力 | 分别提供/消费什么，边界怎样划分 | |

## 用户焦点的运行闭环

用户焦点若是一个业务环节或工作台，不能只讲当前最容易找到的代码纵切。根据材料合并或调整下列阶段；确实不适用时写业务理由。

| 运行阶段 | 读者必须理解什么 | 规范落点/未知 |
|---|---|---|
| 进入条件与准备 | 什么可以进入、依赖什么、失败时停在哪里 | |
| 计划、分配或调度 | 工作怎样拆分、分给谁、形成什么任务 | |
| 实际作业 | 人或系统真正做什么、产生什么结果 | |
| 进度监控与异常 | 怎样知道做到哪里、风险和遗漏怎样暴露 | |
| 分析与决定 | 怎样从事实形成判断，数据不足时怎么办 | |
| 结果执行与外部同步 | 决定怎样生效，外部系统或下游怎样确认 | |
| 返工、恢复与结束 | 失败怎样回退重做，什么条件才真正完成 | |

## 读者问题主线

问题决定阅读和页面，不按材料目录顺序摘抄。根据实际任务选择所需问题；不适用项写理由。

| ID | 读完后必须能回答的问题 | 所需深度 | 需要哪类直接事实源 | 候选来源 | 规范落点/未知 |
|---|---|---|---|---|---|
| Q1 | 主题位于什么上级领域，为什么存在，与同级能力怎样分工；若没有上级，证据是什么？ | | | | |
| Q2 | 主题从哪里开始，到什么结果才真正结束；哪里并行、异常或返工？ | | | | |
| Q3 | 分别有哪些角色、核心对象与状态、平台/业务模块；每个模块的职责和输入输出是什么，上下游怎样交接？ | | | | |
| Q4 | 用户焦点怎样从进入条件走过计划/分配、实际作业、监控、分析与决定、结果执行，直到返工或真正结束？ | | | | |
| Q5 | 核心数据、标识、关系、状态、新鲜度和统计口径是什么？ | | | | |
| Q6 | 若涉及软件，代码地图、运行时序、核心类/数据关系怎样共同解释一个业务动作；职责为何这样划分、当前限制和一次修改路径是什么？ | | | | |
| Q7 | 若涉及规则或算法，其输入、输出、不变量、步骤、边界和实现在哪里？ | | | | |
| Q8 | 跨领域公共能力哪些已覆盖、哪些相关但未知或尚未抽取、哪些确实不适用；在哪里维护，本领域只保留什么使用契约？ | | | | |
| Q9 | 哪些是当前事实、人工决定、目标设计、历史做法和未知？ | | | | |
