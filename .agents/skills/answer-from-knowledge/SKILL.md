# 可信知识问答

从知识入口形成**最低充分答案**。普通问答只返回答案，不创建工作区、账本、YAML 或知识变更；用户要求保存、修订或摄入时再切换对应能力。

## 1. 固定问题和精度

先用一句话明确用户要获得什么，并判断答案精度：

- **学习全貌：** 解释位置、主线、关键对象和继续阅读路线；
- **事实判断：** 回答当前知识明确支持的定义、规则、状态或关系；
- **缺口判断：** 回答是否存在、能否确认、哪里冲突以及还缺什么证据；
- **任务上下文：** 为一次开发、排障、方案或业务动作提供会改变下一步的事实、约束、入口和未知。

用户问精确当前代码、Schema、接口返回或运行数值时，知识只负责地图和边界；最终事实必须回到当前源码、机器定义或新鲜运行。用户只问业务理解时，不为显得可靠而无界读取代码。

## 2. 从产品入口定向下钻

优先使用用户指定的知识根；否则从 `knowledge/index.md` 开始。候选知识明确位于某个 `draft/knowledge/` 时，从该候选根入口开始，不能混用正式知识和候选。

1. 读取根入口，根据问题选择一个领域视图、旅程视图或问题直达入口；
2. 从视图链接中选择最多三篇共同回答问题的规范页；导航页不算规范事实，来源页只负责追溯；
3. 逐页提取直接答案、现实状态、适用范围、冲突/未知和继续核验入口；
4. 多部分问题逐项检查，不能用一个相近段落替代未回答部分；
5. 已经能回答时立即停止，不继续浏览整个知识库、原始材料、摄入工作区或 Eval。

若入口或规范页召回不足，用 `rg` 在当前知识根定向搜索用户原词及一个必要同义词；最多选择两个新候选页面。仍不足时报告知识缺口，不把“没有搜到”写成“事实不存在”。

## 3. 判断答案的现实状态

每个会改变用户行动的结论都归入以下一种状态：

- **已确认：** 规范知识给出明确结论，并能回到匹配的业务决定、源码、Schema 或运行证据；
- **历史记录：** 只说明过去怎样做，不能默认当前仍适用；
- **目标设计：** 说明希望怎样建设，不代表已经实现或部署；
- **冲突：** 两个来源、版本或口径互不兼容，当前没有足够依据裁决；
- **未知：** 知识明确缺证据，或当前检索不足以可靠回答。

不要输出伪精确的置信分。结论跨越不同状态时拆开表达，例如“业务定义已确认；生产实现未知”。知识页与来源页冲突时不自行静默选边；优先指出冲突并说明裁决需要哪类直接事实源。

## 4. 只在必要时回到直接事实源

满足以下任一条件才继续读取直接事实源：

- 用户明确要求当前代码、接口、Schema 或运行结果；
- 规范知识标记内容可能过时或有冲突，且当前项目内存在授权的直接来源；
- 答案将直接决定高风险修改或不可逆动作。

先沿规范页给出的来源或代码入口读取最小文件/符号。没有授权路径、环境或当前版本时停下，明确需要谁提供什么；不要递归翻仓、读取 `knowledge/raw/`，也不要把目标设计或历史报告升级为当前事实。

## 5. 交付可直接消费的答案

先给结论，再按问题需要选择最少的结构：

1. **直接答案：** 用普通语言回答问题，不先介绍检索过程；
2. **已知、未知与冲突：** 只列会改变理解或下一动作的边界；
3. **依据：** 链接具体规范页；读取了直接源码/Schema/运行结果时单独标明；
4. **下一步：** 知识充分时说明无需补充；有缺口时说明最小责任人、事实源或验证动作。

任务上下文额外给出一个紧凑交接：用户结果、必须保持的规则/边界、可能的实现或排障入口、最低验证路径、仍会改变方案的未知。不要把三篇知识全文拼成上下文，也不要替后续任务预先完成完整方案设计。

## 完成标准

- 原问题的每一部分都有答案或明确缺口；
- 已确认、历史、目标、冲突和未知没有混写；
- 依据使用可点击的具体知识路径，引用不能代替答案；
- 阅读范围能说明为什么已经足够，没有无界翻库；
- 没有用户授权时不创建文件、不修改知识、不读取原料或外部项目。
