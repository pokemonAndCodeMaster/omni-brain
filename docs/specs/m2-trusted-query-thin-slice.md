# M2 可信知识问答薄切片

> **状态：** `Verified@quality-check-trusted-query-slices`。已由固定路由评测和弱模型盲问答验证；采用范围只包括当前中文 Markdown、单一质检领域和最多三篇规范页。

## 用户结果

用户在带正式知识的项目根直接提问，得到一份可立即用于学习、判断或开始任务的答案。答案明确已确认、历史记录、目标设计、冲突和未知，链接具体知识页，并在知识不足时给出最小补证动作。普通问答不暴露工作区、YAML、账本或摄入过程。

## 触发与输出

```text
自然语言问题
→ 判断学习 / 事实 / 缺口 / 任务上下文
→ 确定性路由器从受治理知识中给出主入口和差异化候补
→ 先读主入口；只有明确未回答项才打开候补
→ 最多三篇规范页；路由不足时才做有界搜索
→ 形成直接答案、可信边界、依据和下一步
```

输入是用户问题与用户指定或项目默认的 `knowledge/index.md`。输出只有聊天答案；只有用户明确要求保存或修订时才进入其他能力。

## 技术取舍

首版采用 Markdown 根入口、产品视图、规范页链接和 `rg`。基础 Trial 证明：简单问题可以有界回答，但复杂多部分问题仅靠提示中的停止规则仍会宽泛搜索、探测不存在的源码目录或把三页上限误当成阅读目标。

因此新增 `.agents/skills/answer-from-knowledge/scripts/knowledge_route.py`：

- 只遍历 `knowledge/index.md` 及受治理导航页可达的 Markdown，不读取原料和未链接副本；
- 使用链接标签/上下文、frontmatter、标题、正文词项和中文短词项做可重建排序；
- 多部分问题按子句提供不同候补，避免候补都重复回答同一部分；
- 返回绝对现存路径，不回答问题、不写索引、不保存状态，也不把排序分数声称为事实置信度。

当前正式知识只有数十篇且入口已经可维护；向量库、知识图谱、全文索引或查询状态机不会直接解决“历史/目标/当前混写”和“无界阅读”，反而会引入索引一致性与部署成本。

只有真实 Trial 出现以下证据才升级技术：入口召回稳定漏失、同义表达无法有界定位、知识规模使三页规则失效、关系型问题反复需要遍历，或延迟达到不可接受水平。升级时派生索引必须可从规范知识重建，不能成为第二事实库。

## 验证证据

[正式知识可信问答包](../../eval/fixtures/real_work/trusted_knowledge_answer_pack_v1/README.md)固定用户批准的质检知识，覆盖学习、现状、冲突与开发上下文四种日常问题。参考答案和弱模型均受最多三篇规范页的同一预算约束。

基础包结果为 `22/24`，内容超过接受线，但复杂开发上下文发生过读，不能据此宣布完整能力通过。随后两轮邻接回归验证有限集合完整列举、绝对链接、相对链接解析、一页起读和按缺口下钻，仍发现复杂问题的纯提示停止不稳定。

[知识入口路由评测](../../eval/reports/real_work/knowledge-route-quality-v1-2026-08-07.md)冻结 10 条学习、现状、冲突、算法、人员、交付和公共能力问法，路由结果为 `10/10`。[路由集成盲测](../../eval/trials/real_work/TRUSTED_KNOWLEDGE_ANSWER_ROUTER_CODEX_LUNA_HARNESS_001/audit.md)再使用未进入前述问答 Trial 的人员权限和交付多状态问题：两题均为 `5/5`，模型真实调用路由器，只读主入口和一个候补，无宽泛搜索、失败命令、源码探测或文件修改。

通过要求仍是：内容题达到用例阈值且关键题全过；没有无授权写入；引用可达；没有无界读取；答案对用户可直接消费。结构正确、读取文件少或模型声称“已确认”都不能单独构成通过。

## 失败与降级

- 入口召回不足：用原词和一个同义词做有界 `rg`；仍不足则报告知识缺口。
- 精确当前行为：沿知识给出的入口读取最小源码、Schema 或新鲜运行结果；没有授权或环境则停止。
- 状态冲突：保留冲突，说明直接证据与责任人，不自行选择。
- 路由器无结果或候补明显不相关：回到根入口做一次定向搜索并明确路由缺口，不无界遍历。
- 超出已验证范围：允许使用本能力作为有界起点，但必须标为试用；精确当前行为仍以源码、Schema 和运行结果为准。
