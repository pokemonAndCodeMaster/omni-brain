## 0. 2026-07-05 工作台深化决策

验收中心的四个视图全部使用统一数据工作台，不另造简化表格。

1. **任务队列**：任务聚合行呈现综合快照全部字段，并展示最近有新增标注的若干日期；默认过滤零进展日。按天展开后，每个日期行是验收分配的最小可选单元，仍支持筛选、勾选、导出和统计。
2. **验收分配**：默认筛出可分配任务/日期。选择范围后选择 GroupSampler、PersonalSampler、RatioSampler 或自定义约束求解；自定义约束支持分组、项目、任务、日期、选项维度的上下限、目标量和比例。生成预览后展示配额、实际可选 task、Good/Bad、组/scene/人员分布、缺口和警告；可排除任务或覆盖局部参数后重新求解，再确认执行。
3. **通过打回**：选择范围和规则后预览 PASS/REJECT/PENDING、完成度、Good/Bad/整体通过率、阈值和具体执行数。PENDING 不可执行；执行前后端重新聚合并校验数据版本。
4. **质量分析**：提供团队默认布局和个人布局；默认覆盖进度、质量、效率、打回原因、人员/组/任务对比。任意当前筛选结果可一键生成图表并保存为个人关注卡片。

### 预览出现条件

分配预览和通过打回预览默认不存在。只有用户先选择任务/日期叶子行，再点击"生成预览"后才出现；没有选择时按钮禁用并解释原因。修改选择、筛选、规则或约束后，旧预览立即标记失效并收起，不允许带旧结果执行。

2026-07-06 首版已接入真实 preview API：页面显示冻结单元、可用量、Good/Bad 计划、缺口、日期明细、preview_id 和有效期；选择变化触发失效。真实 Delta 尚未接入，因此确认分配按钮明确禁用。实现契约见 [[人工质检验收分配预览闭环设计]]。

总览页不直接编辑高风险状态。验收中心内部允许具备权限的用户完成分配、通过、打回，但必须经过预览、确认、执行和回查。

## 1. 页面任务

验收中心放大交付轨道中的验收阶段。第一屏先展示所有数据集交付任务的验收注意力，不直接让用户面对采样表单或 task 明细。

页面分两级：

```text
/manual-qc/acceptance                  验收中心总览
/manual-qc/acceptance/:deliveryId      单需求验收工作区
```

## 2. 验收中心总览

```text
┌ 验收中心 ─────────────── [进度] [质量] [效率] ┐
│ 待分配 5｜验收中 8｜进度风险 3｜待结论 2｜返修中 4｜异常 1 │
├─────────────────────────────────────────────┤
│ 常用筛选                              [高级筛选] │
├─────────────────────────────────────────────┤
│ 数据集交付任务级列表                         │
└─────────────────────────────────────────────┘
```

顶部队列可点击过滤。默认按注意力排序：异常/部分失败、已满足结论条件、临近交付、待分配、正常验收中。

## 3. 数据粒度与下钻

默认一行对应一条数据集交付任务；逐层展开：

```text
交付任务
└── scene
    └── 组
        └── 标注员/验收员
            └── task 明细
```

总览不直接加载全部 task。用户从异常数量、人员、scene 或指标点击下钻；task 明细使用抽屉或独立明细区，保留返回时的筛选与展开状态。

## 4. 三套列视图

### 4.1 进度视图（默认）

显示：数据集任务、目标交付、应抽、已分配、已验收、验收完成率、预计完成、验收剩余时间、当前轮次、健康状态、下一动作、更新时间。

### 4.2 质量视图

显示：Good/Bad 样本量、Good/Bad/整体通过率、通过量、打回量、主要打回原因、当前结论和结论依据更新时间。

任务级最小完整指标组为：验收分配总数；Good 分配、通过、打回的数量和比例；Bad 分配、通过、打回的数量和比例。其中 Good/Bad 打回数分别由 `allocated - passed` 得出，比例分母是各自分配数。

### 4.3 效率视图

显示：验收员数量、今日完成量、人均标效、平均耗时、积压量、低效对象、预计清空时间。

验收标效按天聚合，任务队列同时显示当日值和近期趋势；不将全周均值冒充当日标效。

三套视图共用筛选和行层级；用户可保存自定义列配置。指标缺少稳定口径时显示"待定义"，不把不同统计口径伪装成同一指标。

## 5. 单需求验收工作区

工作区头部保留交付上下文：任务、优先级、目标/预计交付、验收预留、当前轮次、健康状态和下一动作。

主体标签：

```text
总览｜验收任务分配｜验收监控｜结果分析｜结论与返修
```

### 5.1 总览

浓缩展示：应抽、预期/实际分配、已完成、完成率、Good/Bad/整体通过率、当前结论、预计验收完成、风险和下一动作。

总览不堆满图表；每个指标都能点击进入对应标签并自动带入筛选。

### 5.2 验收任务分配

采用左右分栏：左侧范围与采样策略，右侧分配预览。预览展示 Good/Bad 配额、scene/组/人员分布、具体任务数、数据不足和供应商冲突等警告。

交互状态：

```text
编辑条件 → 生成预览 → 预览完成 → 确认分配 → 执行中 → 结果摘要 → 回查中
```

条件变化后旧预览整体标为失效；执行中禁用重复提交；结果区分别展示请求、实际发送、成功、跳过、失败和待回查数量。

### 5.3 验收监控

展示：

- 应抽、预期分配、实际分配和差额；
- 已完成、处理中、失败和积压；
- 按验收员、组、scene 的进度与标效；
- 预计完成时间与交付风险；
- 无进展、速度过低、状态异常的对象；
- task 明细及异常原因。

趋势图必须能下钻；标效排名同时显示样本量，避免小样本误判。

### 5.4 结果分析

展示：

- Good、Bad、整体通过率与阈值；
- 通过/打回数量及比例；
- scene、组、标注员、验收员维度切换；
- 打回原因横向条形图与明细；
- 多轮验收结果对比；
- 低通过率、低标效和异常分布对象。

通过/打回比例使用分段条和明确数值，不用难以精确比较的饼图；趋势使用折线；原因排序使用横向条形图。

### 5.5 结论与返修

结论面板同时展示 decision、自然语言原因、完成度、Good/Bad/整体通过率、阈值、规则名、影响范围和更新时间。

- PENDING：说明缺少什么，不展示执行按钮。
- PASS/REJECT：有权限用户确认范围后执行。
- 执行后留在当前页，状态进入执行/回查，不只弹成功 Toast。

REJECT 后继续跟踪：打回数量、已重新分配、返修中、返修完成、待重新验收、当前轮次以及相对上一轮的指标变化。全部任务处于通过或打回只说明本轮验收结束，不等于整条交付任务完成。

## 6. 跨页面导航

- 交付中心"待验收"进入验收中心并带入筛选。
- 交付任务"分配验收"直接进入对应工作区的分配标签。
- "确认结论"直接进入结论与返修标签。
- 验收中心返回交付中心时保留原关注集合和列表状态。
- URL 可表达 deliveryId、标签和关键筛选，支持分享和深链。

## 7. 前端反馈与可访问性

- 超过 300ms 的查询显示骨架或局部加载状态。
- 写操作按钮显示进行中并防止重复点击。
- 错误说明原因与恢复动作；部分失败保留成功结果，仅重试失败子集。
- 状态不只依赖红绿颜色，同时显示文字和图标。
- 图表提供数值表格替代视图；tooltip 支持键盘访问。
- 明确显示统计时间和最近刷新时间，避免把延迟数据误认为实时数据。

## 9. 可交互原型

`prototypes/manual-qc-demo/index.html` 已实现验收中心的前端交互样稿，和交付中心共用同一单文件运行：

- 验收中心任务级总览，以及进度、质量、效率三套列视图；
- 单任务验收工作区的总览、分配、监控、结果分析、结论与返修标签；
- "编辑条件 → 生成预览 → 确认分配 → 进入监控"的连续交互；
- 通过/打回分段条、原因横向条和 PASS 结论确认反馈。

原型内的分配执行、结论提交和状态回查都是前端模拟反馈，刷新页面后不会持久化。它的用途是评审页面主线和操作上下文，不用于验证业务规则计算或真实执行安全性。
