# M1 私有消费参考

> 只供候选运行结束后的评测者比较，不得暴露给摄入模型或知识消费候选。以下不是要求逐字匹配的唯一答案，而是获批学习覆盖矩阵下的关键事实与边界。

## 1. 人工质检在质检领域中的位置

现有材料把质检分成人工质检、自动化质检、大模型质检和专题数据质量。人工质检由人完成复杂语义判断，在城区、高速、园区、仿真等材料场景中可能处在交付前最后一环；感知更多是抽检防护。其他方式提供产线规则、模型能力或专题长期质量结果，同一需求可能组合消费，但责任不能混写。

## 2. 人工质检端到端生命周期

需求登记与接纳 → 数据送检，同时推进规则/适配/培训 → 任务创建与生产 → 标注分配和执行 → 验收分配和抽样验收 → 形成结论并执行通过/打回 → 回查外部状态 → 通过后判断可交付 Good 数量并归档，打回后返工、重新提交和再次验收。数据与规则可并行，新规则会多轮对齐，REJECT 不是终点。

## 3. 人工质检模块与验收上下游

总览发现主要矛盾，交付中心维护交付任务和行动项，规则/适配与任务生产准备作业输入，标注中心产生结果，验收中心完成分配、监控、分析、结论和返工，人力与分组提供人员。验收接收标注结果和人员/规则/任务上下文，输出质量依据、执行状态、返工或可交付判断给交付主线。

## 4. 验收闭环

选择总体 → 计算配额和样本 → 分配给验收员 → 完成样本判断 → 汇总完成度和质量 → 得到 PASS/REJECT/PENDING 等结论 → 人工确认范围 → 执行前重取当前数据 → 对决定范围内标注全集通过或打回 → 回查真实状态 → 交付或返工。样本、结论、执行全集和最终状态不能混为一体。

## 5. 数据、标识、状态和口径

交付任务是管理主对象，`scene_name` 是一批任务的管理/统计标识，task/clip 是最小作业与执行对象，目标快照按日期/scene/组/人员聚合计数，预览保存一次选择和结果。交付阶段、健康状态、行动项状态和验收结论必须分开。推荐把实际分配/预期分配作为分配达成，完成/分配作为进度，通过/完成作为质量；最后一项与另一来源冲突，需业务确认。

## 6. 系统跨层协作

工作台表达用户任务，FastAPI Router/Pydantic 形成 HTTP 边界，Service 串联用例，纯 Python 算法计算配额或结论，Repository 访问本平台数据库，公共数据库组件管理连接，目标 DeltaClient 调外部任务系统。固定代码只有查询与 Ratio 预览；外部调用、调度和结论执行仍是目标或历史。

## 7. Python 软件结构与设计判断

当前预览链为 `router.py → AssignmentPreviewService → AcceptanceRepository + plan_ratio_sampling → PostgresConnector`。选择从 Pydantic 请求变成 task/date keys，再变成 Repository 字典行、`SamplingBucket`、`SamplingPlan` 和响应 JSON。薄 Router、纯算法、集中 SQL 和依赖组装使当前切片清楚；限制是 Service 直接依赖 API Schema、Repository 可能继续膨胀、多策略注册表并未实现、预览不固定 task_ids。评价必须基于这些实际代码，不按模式名称数量打分。

## 8. 公共能力与领域契约

`src/database/` 的连接池、命名连接、事务和通用查询属于公共能力；人工质检表、SQL、字段和事务语义属于领域。OBS 在目标材料和用户确认中是公共能力，但固定代码只有占位目录；验收目前只能声明缺口，不能虚构客户端。领域页面只应写用途、输入输出、依赖保证和失败影响。

## 9. Ratio 与其他策略

Ratio 输入桶的 Good/Bad 可用量、目标总数和 Good 比例。目标不超过总可用量，超额形成 shortage；Good 用 Python `round` 计算，一侧不足由另一侧补。每类按容量比例分桶，先向下取整，再按小数余数从大到小补，同余数按 ID 稳定排序，桶不超容量。Group/Personal 的 90、300、50% 等来自历史与目标，当前代码未实现。

## 10. 结论与执行

历史脚本使用完成度 95%、Good/Bad 覆盖 90%、Good 严格 `>0.9499`、Bad 严格 `>0.7999` 等规则，但只能标历史。目标规则在数据不足时返回 PENDING 并禁止执行；执行前重算，之后作用于范围内标注全集。接口即时成功不等于最终落地，超时或部分失败需要从外部状态回查实际成功量。

## 11. 当前、目标和历史

固定代码实现任务查询、日期展开、metadata、Ratio 数量预览和按创建人读取预览；没有正式分配、结论、DeltaClient、回查或返工。目标材料描述完整工作台、Sampler/Rule、Service、快照和外部调用。历史材料记录旧脚本阈值、状态和两次 rollback。三者必须分开。

## 12. 当前未知和补知责任

生产 Delta 接口/状态找外部系统负责人；生产快照 DDL、血缘和新鲜度找数据负责人；当前采样/阈值/口径/执行范围找业务负责人；部署与端到端启动找原型维护者；材料声称的后续实现需提供对应仓库提交。没有这些证据时应回答未知，而不是从目标文档推断。
