# 当前发布能力

> 最近更新：2026-08-14。

## 当前状态

这是统一 `release/harness` 分支上的集成 Harness Release。发布对象是可移植的工作方式与工具，不是某次模型生成的知识答案；知识摄入、查询、开发、回写和本地审查分别按 `harness.yaml` 声明的验证范围采用，不再为每项能力建立新的远端发布分支。

实施前方案形成能力已经加入候选：复杂或模糊开发诉求先在唯一 `review.md` 中形成 R1 需求，用户确认后才定向读取当前实现并形成 R2 方案，R2 通过后才进入开发。当前仍待固定较弱模型完成正向多轮重放和两类负向路由回归，尚未升级为已验证能力。

M2 可信知识问答薄切片已经在当前质检范围取得验证证据：用户从项目根提问时，`answer-from-knowledge` 先用只读入口路由器选择一个主知识页，再按需读取最低充分规范页，明确已确认、历史、目标、冲突、未知和下一补证动作。确定性路由在十个问法上通过；固定较弱模型在新的人员权限和交付状态问题中实际调用路由、零宽泛搜索并取得完整内容结果。普通问答不产生工作区或中间文件；证据尚不能外推到第二领域、OpenCode、大规模知识或精确源码联查。

基础文档整理、聚焦代码整理和存量知识增量融合均已有真实材料内容证据；同一增量用例已经通过人工批准、正式知识消费和两个独立模型重放。成熟度只到首个质检增量切片，不能外推为跨领域、OpenCode 实际宿主或任意规模已经验证。

同一个 `ingest-knowledge` Skill 提供两条最低充分路线：

- **宽范围完整整理：** 固定材料 → 可完整阅读的材料单元 → 带必要细节和精确定位的发现 → 长期知识主题 → 发现到正文标题映射 → 产品视图与来源追溯；
- **聚焦代码或问题：** 明确问题 → 小批直接来源 → 规范知识 → 需要时在隔离环境真实运行。

用户只需从项目根目录提出自然语言请求，最后审查候选知识、产品视图和 `review.md`。后台状态仍只有 `.state/case.json` 与 `.state/source-manifest.jsonl`。

当前正式知识库为空。首次使用会从用户授权材料形成候选；已有正式知识时，工作台会冻结父版本文件指纹并把它原样复制到候选，本次只扫描新增材料。知识主题显式区分新增、原位更新和合并，审查页展示父版本到候选的实际差异。未计划的正文/视图修改和父知识删除会阻止发布准备。

## Harness 效果证据

- 不重复叙述文档独立审阅，发现保留必要细节和精确定位，并唯一归入一篇规范正文、映射到真实标题；
- 完整整理已在一批固定真实材料上形成规范知识、产品视图和可追溯来源，并达到预定内容接受线；
- 模型手写来源路径曾出现错误，现改为从已校验来源、发现和正文落点自动生成追溯视图；
- 回归、Skill 校验和候选领域地图下的知识检查通过；
- 父版本继承、原位融合、旧来源保留、入口语义同步和产品视图更新已在真实增量材料上完成；
- 另一独立模型能够依靠持久工作台跨会话继续同一长任务，并形成达到相同内容线的候选；
- 候选经过人工批准发布后，干净消费会话无需读取原料即可回答约定问题并明确生产未知；
- 本 Release 保持空知识骨架，证明领域知识产出没有被硬编码进 Harness。

这些证据证明的是 **Harness 在声明切片上的效果**。具体质检知识只是测试输入产生的可观察结果，保存在独立集成版中。

## 当前边界

- 读后发现、知识归属和正文表达仍由模型完成；工具只校验来源、顺序、一致性和可重建关系，不判断业务真伪；
- 逐文档审阅提高内容保真，也增加了命令与阅读成本，仍需在后续用例观察人工与模型负担；
- Python 包、模块、函数和方法细节在主题合并时仍可能被压缩；
- 缺少直接证据的 OBS、真实 Delta、生产状态和规则边界只能保留为未知；
- 候选领域配置必须随知识一起人工审查，不能自动修改正式分类；
- 增量新增、原位更新、父知识保留、冲突/未知保留和产品视图同步已有跨模型切片证据；
- 已发布质检知识的消费会话能够给出正确范围答案，但仍有读取范围偏大的现象；这是 M2 查询与上下文节制问题，不再扩建 M1 摄入流程；
- 当前查询只有 Markdown 入口路由与有界阅读，没有全文/向量/图检索或 Web 界面；代码变化回写在同一质检系统相邻增量上已经达到冻结内容接受线，但尚不能自动发布且仍需人工内容审查。

## 使用方式

1. 在项目根目录用自然语言指定材料路径和需要建立的知识；
2. Harness 在隔离工作台形成候选知识、产品视图和唯一 `review.md`；
3. 用户审查后决定批准、退回或拒绝；批准前正式知识保持不变；
4. 发布后从正式 `knowledge/index.md` 浏览和消费知识。

M2 查询与任务上下文已在当前质检 Markdown 切片验证；它不是全文、向量或图查询引擎，也尚未通过第二领域或 OpenCode 反证。

## 实验中的开发能力

当前分支提供 `develop-with-knowledge` Skill，用于需要业务知识、跨层修改或真实运行验证的软件开发任务。它要求先固定用户结果，以最多三篇会改变实现的正式知识作为初始上下文，并在首次编辑前公开用户结果、责任链、受影响集合的最大合法组合和真实验证计划；随后沿现有纵切完成最小修改。

该能力还要求在真实数据库、API、CLI 或页面中验证正常与关键边界，并形成带有来源身份、变化事实、规范落点、保持边界和证据的知识变化候选。它不自动发布正式知识，也不自行安装依赖或管理环境。

该能力已经在四类开发切片中取得真实证据。验收配额切片中，同一弱模型从两次遗漏完整组合，改善为自主算出并运行 9 个固定指标 + 5 个不同问题选项，14 项通过、15 项拒绝，保存五个固定选项后的 Edge 页面仍加载 24 个任务。只读 SQL 切片中，模型从真实页面请求和执行计划定位到无关 JSONB 标签展开，保持接口与结果不变，只修改一条 Repository 查询，在 151200 行负载上把交错测量中位数降低约 20%，独立正常夹具回归通过。

第三个验收分配缺口切片要求 Catalog、Repository、HTTP、Vue 映射和任务表保持同一业务语义。弱模型自主发现新增后的 10 + 5 组合边界，并按 Good/Bad 最终分类计划计算原子缺口；固定数据库、最大 15 项通过且第 16 项被拒绝的 API，以及 Edge 四级下钻均通过。该候选还反证了首轮专家参考把 Good/Bad 再次互抵的错误，参考已由运行和正式知识共同修正。

第四个缺口详情交互切片在相同宿主、模型、产品、知识和任务下做了 Harness 前后对照。首轮业务功能可用但没有完成焦点进入、Tab/Shift+Tab 环绕和关闭后恢复，最终声明也超过观察；修订后的通用开发 Skill 让第二轮自主处理行重渲染后的焦点恢复，真实数据库、HTTP、四级页面、零分母、完整键盘和全量回归均通过。修订只涉及来源追踪、短运行探针、交互证据和交付映射，不包含本题公式、数字或组件名。

随后“验收未完成量”首次把 M2 知识路由与 M3 开发放入同一个复合任务。较弱模型实际调用路由，只读两篇正式知识后停止，发现后端已有指标并只接通前端消费链；最大组合与超限拒绝、真实 API、Edge 排序/筛选/下钻和全量回归通过，并达到冻结接受线。模型页面验证使用了错误的默认日期 Scope，知识交接也未指向正式 owner；规则已按这两个真实缺口修订。开发能力当前是 **同一质检领域四类开发切片 + 一个可信上下文复合切片内已验证**；证据覆盖两种宿主/模型组合，但不代表跨领域或任意软件开发已经验证。

本地 CSV 单事务写库也取得正向证据：通用副作用规则让同一弱模型停止使用动态 `seed/reset`，补了聚焦测试，并实现了 `null`/非空人工状态保护、预览失效、整批拒绝和幂等写入。独立负例仍发现不完整 JSONB 指标可以通过解析，因此数据写入目前只是**可用但待修订的证据**，不提升采用级别。

代码到知识的安全回写随后在“验收未完成量”相邻增量上完成多轮盲测收敛。最终候选准确固定来源 root、branch、HEAD 和 parent，区分验收未完成量与分类原子分配缺口，闭合后端到 Vue 的消费链、旧列配置恢复机制、公共工作台边界、指标组合和真实验证范围，并同步根入口与学习旅程；候选达到冻结内容接受线，正式知识未发布。该能力当前为 **同一质检系统相邻增量切片内已验证**。

不同变化类型的快照导入保留集仍未通过：弱模型能够保留外部列、转换主链、事务与公共数据库能力，但会把源码中的精确类型/范围、报告中的代表性人工状态值和固定日期夹具边界压缩成概述。因此本能力仍必须人工对照直接源码与固定报告，不能自动发布；后续应优先增加通用的契约与运行证据提取，而不是继续为同题增加提示。

## 实验中的本地工作审查

当前分支新增 `review-work` Skill，用于把复杂 AI 成果组织成唯一的本地 `review.md`。它先核对原始问题、实际任务和最终产物是否对齐；对齐时按需求、方案、实现和验证逐阶段审查，错位时停止要求用户批准下游内容。

软件开发分支已经吸收真实人工反馈并形成认证参考。OpenCode DeepSeek 最终正向候选具备入口导航、完整全貌、需求—方案—实现—验证的顺序、跨层图示和可填写审查点，达到认证参考接受线；负向错位只读取任务身份包后停止，简单状态问题不触发审查单。因此该能力在这三类软件工作切片内标记为 verified。它仍不包含证据采集脚本或需求方案生成能力，也未验证知识摄入、方案和 Harness 修改的专属审查。
