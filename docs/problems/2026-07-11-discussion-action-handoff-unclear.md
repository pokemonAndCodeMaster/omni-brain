# 讨论回复缺少明确行动交接，用户难以判断如何继续

## 1. 场景与用户目标

用户希望每轮重要项目讨论结束后，能够快速知道本轮形成了什么、自己需要做什么、Agent 会做什么，以及不同互动选项会触发什么结果，而不必理解仓库内部术语或自行从长篇分析中提炼下一步。

## 2. 观察到的问题与影响

此前回复虽然给出“已确认、暂定、未决、下一步、沉淀候选”等分类，但仍存在：

- 不清楚每一项对当前任务意味着什么；
- 不清楚哪些需要用户行动，哪些由 Agent 直接完成；
- “建议沉淀、更新规则、加入知识库”等表达没有解释触发结果；
- 开放式建议没有责任人、输入、产物和验收；
- 读者若缺少项目背景，需要反复阅读或继续追问才能行动。

影响是对话阅读负担增加、决策和授权延迟，也可能让有价值的结论停留在聊天中而未进入正确流程。

## 3. 分诊与根因假设

| 层 | 判断 | 根因假设 | 置信度 |
|---|---|---|---|
| 阅读视图（主层） | 结论存在但缺少鲜明、可执行的结果视图 | 回合收束只展示内容状态，没有展示互动与责任 | 高 |
| 工作流与治理 | 用户不了解内部术语会触发什么流程 | 操作契约存在于项目文件，但未转译为当前情境的交互选项 | 高 |

该问题不是要求每轮强行产生新结论或行动；探索性回合也可以只明确新发现、未决问题或验证方式。

## 4. 本轮改进实验

1. 在 `AGENTS.md` 增加“本轮决定 + 现在怎么继续”的行动交接硬规则；
2. 在对话生命周期协议中定义用户动作、Agent 动作、预期产物、无动作影响和替代路径；
3. 建立常用互动表达及触发结果，首次用于当前情境时由 Agent 解释；
4. 简单回答不强制模板，无需用户行动时明确说明；
5. 后续五轮非简单讨论按新规则试行，再复查字段是否机械、冗长或仍不清楚。

## 5. 验收条件

- 用户无需了解仓库内部术语，也能指出当前推荐路径；
- 需要用户行动时，回复给出可直接使用的表达或明确输入；
- Agent 的后续动作和预期产物清楚，涉及文件变更时说明范围；
- 无需用户行动时不制造选择；
- 已确认、暂定和未决没有混淆；
- 连续讨论中用户因“不知道接下来做什么”而追问的次数下降；
- 收束块没有显著增加重复和阅读负担。

## 6. 当前结果

状态为 `experimenting`。规则已更新，尚无五轮使用证据，不能标记为 `resolved`。
