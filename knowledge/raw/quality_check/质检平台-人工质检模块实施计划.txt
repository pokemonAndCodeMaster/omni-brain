## §3 关键实现契约（快照刷新四级契约）

> 本段从 [[验收前置条件-快照刷新四级实现契约]] 提取核心契约摘要。完整契约以原卡为准，本段为可实施摘要。

### 3.1 核心目标

实现统计快照表 `t_qc_daily_snapshot` 的定时刷新机制——每 30 分钟从 Delta 原始表聚合标注进度与验收结果，UPSERT 写入快照表，同时匹配 `t_data_check_screeners` 当前组别信息（team_leader 字段，WHERE end_time IS NULL）冗余写入 `group_name`。

### 3.2 数据流

```
Airflow DAG (每30min)
  └→ StatService.refresh_snapshot(stat_date_range)
       ├→ SnapshotRepository.fetch_annotation_raw(stat_date_range)
       │    └→ SELECT FROM delta.ods_t_label_screening_task_datalake JOIN delta.ods_t_label_sdobject_datalake_new
       │         按 (DATE(submit_time), task_screener, scene_name) 聚合
       ├→ SnapshotRepository.fetch_acceptance_raw(stat_date_range)
       │    └→ SELECT FROM delta.ods_t_label_screening_task_datalake
       │         WHERE task_status IN (67,68,69,70) 按 (DATE, screener, scene) 聚合验收结果
        ├→ ScreenerRepository.get_current_groups(employee_ids)
        │    └→ SELECT employee_id, team_leader, project_name FROM t_data_check_screeners WHERE employee_id IN (...) AND end_time IS NULL
        ├→ StatService._merge_with_personnel(raw_stats, personnel_map)
        │    └→ 将 task_screener(=employee_id) 映射到 employee_id + group_name（group_name=info.team_leader）
       └→ SnapshotRepository.upsert_many(merged_rows)
            └→ INSERT INTO t_qc_daily_snapshot ... ON CONFLICT (stat_date, scene_name, group_name, employee_id)
               DO UPDATE SET annotation_*=EXCLUDED.annotation_*, ... (不含执行字段)
```

### 3.3 四级契约摘要

| 层级 | 契约摘要 | 关键约束 |
|---|---|---|
| **DDL** | 4 张表双 schema 镜像（pnc_simulation + data_common_4），migration 幂等 | 禁 TRIGGER；updated_at 由应用层；`t_data_check_screeners.project_name` 单值；PG10+ 兼容 |
| **Repository** | SnapshotRepository（10 方法）+ ScreenerRepository（6 方法，V20260714_01 改名自 PersonnelRepository） | 全部 SQL 集中 Repository，Service 层禁拼 SQL；禁 ORM；参数化 `%s` 占位；upsert_many 用 `execute_values`，禁 `execute_query` 写；UPSERT 的 UPDATE SET 仅含统计列，禁触碰执行字段；显式带 `updated_at=now()`；SCD Type2 查询含 `WHERE end_time IS NULL` |
| **Service** | StatService.refresh_snapshot(stat_date_range) → int；`_merge_with_personnel` 映射 task_screener → employee_id + group_name | 人员不存在时跳过并 warning；`team_leader=''` 记录空串；scene_name 提取：e2e 项目 `SPLIT_PART(task_name, '_', 2)`，vpd 项目 `SPLIT_PART(task_name, '_', 3)`；`annotation_pending = total - submitted`（CHECK 约束保证非负） |
| **DAG** | `qc_snapshot_refresh` DAG，PythonOperator 调用 StatService.refresh_snapshot | `schedule_interval=30min`；`max_active_runs=1`；`dagrun_timeout=28min`；`catchup=False`；`retries=1`；`retry_delay=2min`；刷新最近 4 天；DAG 内禁业务逻辑；复用 `wrapper_failure_callback` |

- **good_pass_rule**（revoke_and_pass.py:62-63）：`(good_bad验收总数 >= 总验收数 * 0.9 and 总good通过率 > 0.9499) or (good_bad验收总数 < 总验收数 * 0.9 and 总通过率 > 0.9499)`
- **bad_pass_rule**（revoke_and_pass.py:64-65）：`(good_bad验收总数 >= 总验收数 * 0.9 and 总脏数据通过率 > 0.7999) or (good_bad验收总数 < 总验收数 * 0.9 and 总通过率 > 0.9499)`
- **完成度前置**（revoke_and_pass.py:417-418）：`总验收数 >= 应抽数量 * 0.95 or 总验收数 >= 总提交数 * 0.95`
- **应抽数量**（revoke_and_pass.py:416）：`300 if 组员数量 * 90 >= 300 else 组员数量 * 90`
- **边界**：严格 `>`（大于），非 `>=`
- **占比兜底**：当 good_bad 验收总数 < 总验收数 × 0.9（Good/Bad 样本占比不足 90%）时，用总通过率 > 0.9499 兜底

### 5.8 隐式回查机制

- 旧版通过 `delta.ods_t_label_screening_task_datalake.task_status` 判断接口是否成功（assign_acceptance_task.py:262-294 `validate_assign_api_result`）
- `while un_success_task_ids:` 循环重试未成功任务
- `time.sleep(5~10)` 间隔（assign 段）/ `time.sleep(1~2)` 间隔（review/acceptance 段）/ `do_time_sleep(seconds=60)` 间隔（revoke 段两次调用之间）
