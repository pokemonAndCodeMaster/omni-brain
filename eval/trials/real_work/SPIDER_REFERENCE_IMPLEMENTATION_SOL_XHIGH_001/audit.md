# Spider 多源信息平台参考实现审计

## 结论

参考实现已经形成可运行产品主链，并安全进入 Spider 仓库本地功能分支
`feature/multi-source-information-platform-v1@5414aaf`。它没有覆盖原先大量未提交变更的 `main`；
独立工作区可直接安装、构建和运行。当前唯一需要用户亲自完成的产品步骤，是南+受保护板块首次
登录时在可见浏览器中输入验证码。

## 实现内容

- 单一 `ConfigLoader` 读取 `config/settings.yaml`、本地 `.env` 和进程环境覆盖；
- 网站会话/认证与网站信息提取分离，实际实现原站点和 South Plus；
- 采集服务负责有限并发、逐项失败隔离和可观察进度，信息入库服务负责事务与分类；
- 六张 PostgreSQL 信息库表与唯一 Repository，区分列表快照、详情、图片、下载、分类和个人状态；
- FastAPI 按启动参数绑定信息空间，页面不能越权切换空间；
- Vue 3 + TypeScript 图墙/列表、共享本地筛选、按需详情和图片、收藏、偏好、人工分类和带 BOM CSV；
- Alembic 版本化迁移保留旧数据，旧表在接受前仍可回退。

## 主审发现与修正

首版实现的迁移把旧数据库自增 ID 误当成网站业务键，而新采集使用 URL 中的 `tid`。真实只读查询
证明 16,875 条旧记录全部会在后续采集时产生重复。主审没有因为测试通过而接受该结果；修订后，
迁移与 Collector 使用同一身份语义，旧 ID 只作为来源证明保留。验证器逐条比较旧 URL、迁移键和
来源元数据，错误数为 0。

同轮还修正两项设计：详情 GET 不再隐式写“已打开”，而是页面成功呈现后显式 PATCH；采集不再
硬编码十页或两百条业务上限，命令只接受用户明确给出的正整数范围，并输出逐项进度。上述修订
说明参考实现也必须经过独立审查和真实数据反证，不能把强模型或大量测试当成真值本身。

## 尚未关闭

南+ `fid=4` 与原站点门禁都需要用户在可见浏览器中完成人工验证。代码已经提供 Cookie 保存与复用
入口，但没有绕过验证码；因此这不是实现缺口，却仍是“受保护板块真实采集已经完成”这一声明的
必要人工证据。在该证据出现前，只能宣称公开板块和认证机制实现已验证，不能宣称受保护板块实采
通过。
