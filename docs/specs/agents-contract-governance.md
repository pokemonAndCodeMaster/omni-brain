# AGENTS.md 自治理协议

> **状态**：Provisional；先用于后续三次操作契约变更，再决定是否固化预算和检查器。  
> **目的**：让 `AGENTS.md` 保持为 Agent 的小型行为内核，而不是随功能增长变成产品规格、工作流手册和实验日志的合集。  
> **关联**：[Blueprint](../blueprint.md)｜[对话回收协议](conversation-knowledge-lifecycle.md)｜[评测策略](evaluation-strategy.md)

## 1. 职责边界

`AGENTS.md` 负责 Agent 开始工作前必须知道、且跨任务稳定成立的内容：使命与阶段、事实源优先级、任务路由、安全红线、变更与验证底线、详细机制的入口。

以下内容分别下沉：

| 内容 | 规范落点 |
|---|---|
| 某类任务的步骤、分支和完成标准 | `.agents/skills/` |
| 设计理由、对象契约、失败与备选 | `docs/specs/` 或讨论稿 |
| 当前焦点、动态成熟度和实验结果 | `docs/now.md`、task case、`eval/reports/` |
| 确定性参数、状态变化和格式校验 | 脚本、Schema、配置 |
| 输入、预期路径、硬门禁和软指标 | `eval/` |

## 2. 内容准入门禁

新增或扩写规则前逐项判断：

1. 是否跨多个任务/组件适用，或属于不能依赖局部 Skill 的安全红线；
2. 是否会改变 Agent 行为，而非重复模型默认常识；
3. 是否已相对稳定，能够说明触发、动作、失败和降级；
4. 是否不能更准确地由 Skill、工具、Spec 或 Eval 承担；
5. 是否已检查与现有规则的重复、冲突和可合并位置。

任一关键项不满足时，不进入操作契约。实验性能力只保留最小受控入口和降级边界，运行状态留在实验记录。

## 3. 变更纪律

- **替换优先**：先修改已有规则，再考虑新增段落；同义规则必须合并。
- **单一事实源**：操作契约只保存结论和指针，不复制外部机制全文。
- **案例不上浮**：案例名称、单次结果和动态成熟度不长期驻留。
- **命令下沉**：只有跨任务稳定且必须在入口执行的命令留在操作契约；参数细节由工具帮助或 Skill 管理。
- **可删除**：实验规则升级、失败或被工具取代时，应明确删除或收缩，不在后面追加修正版。

## 4. 容量与触发式整理

当前不把任意行数定成产品真理。以现有文件为基线，满足任一条件时必须做一次结构审查：

- 连续三次修改均产生净增长；
- 文件超过约 250 行；
- 同一概念出现在两个以上章节；
- Agent 因规则冲突、错误触发或忽略后半段规则而失败；
- 为修复单个案例准备增加第三条以上局部禁令。

审查输出应说明保留、合并、下沉和删除项，以及对应回归用例。预算用于触发审查，不用于追求形式上的最短文件。

## 5. 验证

### 机械检查

候选 `scripts/check_agents_contract.py` 只检查可确定事项：体量、标题、失效本地链接、Skill 引用、重复片段和禁止出现的动态状态模式。检查器尚未实现前，不得声称已有自动门禁。

### 行为回归

重大变更至少覆盖受影响的代表旅程，例如 A/B/C 路由、显式任务案恢复、依赖不可用降级和未经授权的环境变更。分别观察结果正确性、事实源、Skill 路由、安全行为和上下文成本。

规则只有在行为回归中产生可重复改善时才长期保留；模型偶发的小幅额外读取优先作为软指标，不继续堆叠自然语言补丁。

## 6. 当前验证输入

`acceptance-knowledge-prep` 的两次基础模型重放表明：操作契约能够显著改善任务恢复路径；同时也暴露出把单次实验状态写进内核的沉积风险。该案例只证明准入与回归机制值得继续验证，尚不能证明本协议已跨场景有效。
