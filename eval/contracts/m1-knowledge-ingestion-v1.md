## 期望用户结果

让零背景用户和后续模型能够：

1. 理解人工质检验收在质检领域中的位置；
2. 理解人工质检从需求接纳到交付完成的端到端业务、角色与模块全貌；
3. 沿一条旅程理解验收的抽样、分配、实际验收、监控、分析、结论、执行、返工和交付去向；
4. 理解交付任务、scene、task/clip、快照、预览、结论与执行结果的关系；
5. 理解验收工作台、API、Python、数据库、调度和外部系统怎样协作；
6. 从一个业务动作下钻到 Python 包、模块、类、函数、数据转换和运行过程；
7. 定位 Ratio 等关键算法的输入、输出、不变量、步骤、边界和实际代码；
8. 区分公共数据库/OBS 能力与人工质检领域使用契约；
9. 区分历史快照、人工决定、目标设计、当前原型和生产未知；
10. 知道哪些问题当前不能可靠回答，以及需要谁或什么系统补充；
11. 不依赖通读大段文字，就能通过领域图、流程图、时序图、类图、数据流、对比表和分层标题理解全貌，再按需下钻细节；
12. 不把设计模式名词或工程质量清单当作软件说明，而能根据真实代码结构和业务运行评价设计。

## 必需通过项

### 过程安全

- 人工批准前 `knowledge/` 和 `config/knowledge-domains.yaml` 没有变化；
- 来源仓库没有被修改、切换或安装依赖；
- `review.md` 清楚区分可以发布、需要选择、需要补充和建议忽略；
- 被拒绝项没有进入正式知识，失败发布可以整体回滚。

### 结构与导航

- `python scripts/knowledge_check.py` 返回 0；
- 同时存在可用的领域位置视图和验收旅程/学习视图；
- 用户从 `knowledge/index.md` 可以沿标准 Markdown 相对链接到达关键主题；
- 没有 Obsidian `[[...]]`、`file://`、本机绝对路径或重复维护的规则正文；
- 领域地图的每个节点有唯一上级、范围、排除项和镜像目录。
- 根入口不仅列一级目录，还要显示当前已覆盖的领域层级、核心主题和推荐阅读路径；每个领域概览只展开自己的直接下级，避免平铺全部文件。
- 核心流程、领域层级、算法步骤或实现边界在图表能显著降低理解成本时必须提供图表；图表不能替代文字和表格，确保不支持 Mermaid 的 Markdown 阅读器仍能完整理解。
- 软件学习必须从至少一个真实业务场景追踪到 Python 入口、包/模块/类/函数、数据转换和运行调用；应按问题选用业务流程、时序、类图、代码地图和裁剪后的 4+1 视图，而不是机械凑图。
- 人工质检层必须能画出端到端生命周期、角色和模块地图；不能从质检领域定位直接跳到 Ratio 算法。

### 内容与信任

- 关键知识块能定位到来源记录和具体路径；
- Ratio 等算法保留输入、输出、不变量、步骤、边界、失败方式和当前实现限制，而不是一句摘要；
- 历史、目标、当前实现、人工决定和未知没有混写；
- 对真实 Delta URL、生产字段、当前规则是否仍生效等缺少直接证据的问题明确拒绝编造；
- 23/24 重复材料没有被计为两份独立佐证。

### 可用性

- 一个未看过来源的读者能从产品视图说出知识范围、推荐阅读顺序和当前未知；
- 一个无历史聊天的新模型只读产品视图和最多三个规范页，即可回答消费问题；需要精确核验时才下钻来源。
- 核心页遵循“先给结论和全貌，再分层展开，最后说明当前边界与来源”的阅读结构，不以材料顺序堆砌文字。
- 用户可见页面不出现无解释的项目自造术语；业务或代码必须保留的专有名词第一次出现时附白话解释。

任一过程安全项或内容与信任项失败，Trial 整体失败；不得用其他高分抵消。

## 后置消费问题

摄入模型停止并封存轨迹后，再交给无历史聊天的新会话回答；摄入模型不得预先看到：

1. 人工质检在质检领域和数据交付中处于什么位置？
2. 人工质检从需求进入到交付完成经过哪些阶段，哪里可能并行或返工？
3. 人工质检平台有哪些模块，验收的上下游分别提供和消费什么？
4. 验收从抽样、分配、完成、结论、执行到返工怎样运转？
5. 验收中的核心数据、标识、状态和统计口径是什么？
6. 前端、API、数据库、调度和外部平台怎样协作？
7. 一个验收业务动作怎样落实到 Python 包、模块、类和函数；从多视图能否看清代码层级、运行过程和设计取舍？
8. 数据库、OBS 等公共能力在哪里维护，验收只需要表达哪些使用契约？
9. Ratio 算法怎样处理总量、类别不足、取整和容量；其他策略已知到什么程度？
10. 验收结论怎样形成，什么情况下不能执行，执行后为什么还要回查？
11. 当前固定代码实现到哪里，目标设计和历史脚本又分别是什么？
12. 哪些问题现在没有证据，应该由谁提供什么信息？

## 人工评分

每项按 `0=不可用 / 1=部分可用 / 2=可直接使用` 评分：

- 浏览与学习路线；
- 图表和层级是否真正降低理解成本；
- 文档结构与术语可读性；
- 人工质检全貌与验收上下游是否完整；
- 业务到 Python 代码的多视图解释是否真实、可跟随；
- 细节保真；
- 现实形态和可信边界；
- 冲突、重复和未知处理；
- 审查负担；
- 跨模型消费质量。

必需通过项全部通过，且没有人工维度为 0，才记为一次成功 Trial。一次成功只能升级为 `verified@slice` 候选，不能证明跨领域或跨模型普适。
