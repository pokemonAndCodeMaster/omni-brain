# 当前实验工作台

> 最近更新：2026-07-26。

## 当前状态

知识摄入已能在发布前隔离候选并形成局部业务—代码纵切。V10 前向 Trial 证明关键长文可以完整展示；V11 进一步证明 `source-select` 和三层 `knowledge_path` 能让弱模型选中上级来源并建立平台、主题、焦点三个独立落点，但 21 份完整阅读来源只形成五篇实质正文，内容仍为 17/24，且出现两套候选视图路径。V12 当前只清理这两个实际阻塞：统一产品视图位置，并要求每读完一组关键来源就在现有 `inventory.md` 中把不可丢失内容落到规范页、未知或具体排除。当前状态是 `implemented_content_first_v12_awaiting_forward_test`；正式知识仍为空，也没有参考答案或业务评分点进入本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、`source-read` 有界连续展示、`source-select` 关键来源绑定、Agent 覆盖声明、固定根入口、内容声明契约和结构检查；
- `completion.yaml` 的 `parent → subject → focus` 知识主线：每个适用层必须关联已读直接来源和独立正文主落点；
- `inventory.md` 的已读内容落点：关键来源中的机制、条件、边界、冲突和未知必须在继续阅读前关联到具体页面/章节、开放问题或具体排除；
- 候选产品视图唯一位于 `draft/knowledge/views/`：具名视图带 frontmatter，`index.md` 只导航；检查器拒绝旧 `draft/views/` 和重复 frontmatter 键；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 已读内容落点能否阻止弱模型把多份长文压成少数摘要页；
- 数据、软件结构和公共能力能否按独立变化形成稳定知识单元，而不在版本间回退；
- 后置消费者能否按上级、主题全貌和用户焦点的原始问题范围判断完整性；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。
