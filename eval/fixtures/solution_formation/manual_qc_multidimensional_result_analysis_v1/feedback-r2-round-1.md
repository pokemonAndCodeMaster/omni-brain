# 人类对首轮方案的架构反馈

需求已经通过。请只修订 R2，不修改产品代码。

1. 当前代码按 1000 行分页、10000 行阻止继续加载，不代表这就是合理方案。现在不知道真实查询效率、负载、传输和浏览器成本，不能把临时数字固化为业务上限，更不能因此漏数据；先通过实际讨论或实验判断分页实现。
2. 不要创建泛化的 `analysis` Service。这个名字没有边界，任何东西都可以往里放。接口是什么业务功能，就应归属什么功能；本需求属于人工质检快照统计。
3. Router 按人工质检领域组织以后，后端 `src` 也应按同一领域组织；快照数据访问继续由现有快照 Repository 提供，不要再造职责重叠的 `AnalysisRepository`。

其他需求与方案方向基本合理。
