# 本地快照导入代码回写：首轮 Luna 审计

## 当前结论

本轮证明当前 Harness 已经能让 Luna 独立完成一套**可审查、可拒绝、可回滚**的既有知识更新：模型正确识别同一系统的顺序演进，使用隔离工作区修改 13 个既有知识和视图文件，正式知识与产品代码保持不变，结构检查通过，并把 CLI、转换、状态保护、事务、锁、UPSERT 和幂等主线纳入正文。

但候选尚不能发布。按 24 个冻结内容问题独立审查，本轮为 **17/24**，且 C01、C04、C05、C15、C16、I02、S02 七项关键问题未通过。工作台的 `publish_ready` 只说明候选结构和流程可进入人工审查，不能说明内容已经正确充分。

最关键的失败不是格式或声明，而是两类可泛化的理解缺口：

1. 模型把“报告验证实现提交、冻结提交随后只补报告与夹具”的正常祖先关系误判成 commit 冲突，错误降低了真实运行证据的可信度；
2. 模型掌握了高层调用链，却没有把外部 CSV 精确契约、指标不变量、import models 和完整修改入口充分内化，仍需要读者回到源码补齐决定实现和排障的细节。

因此，本轮状态是 **structurally ready but content not certified**，M4 不能凭此晋升。

## 模型实际过程

1. 模型正确路由到既有知识回写，判断新来源属于同一 Quality Platform Lab，而非新系统或早期 Ratio 原型。
2. 它建立摄入工作区，复制父知识到 draft，登记四个读者问题并分批读取 CLI、Service、Repository、迁移、测试和固定报告。
3. 它把新事实原位合并到数据库能力、数据流、采样、实现地图、来源、系统、根入口、领域视图、学习旅程、未知和日志，没有另建“本次更新摘要”。
4. 它在读取固定报告后，把报告正文中的 `c51e232` 与冻结提交 `ea10860` 判成身份冲突，将运行结果标为“报告声称、待人工复核”。
5. 它多次因工作台命令语义恢复：单元路径超过上限、重复单元 ID、`next` 超过 limit、未登记 active packet 就继续、相对 draft 路径错误、把 unit ID 交给以 question ID 为参数的检查命令，以及模板占位符误报。
6. 最终语义复查发现来源导航数量错误并修正；对一个没有实际更新的软件架构页，它先登记为交付路径，随后仅撤销了不必要的改动，但仍把该页写入问题答案。
7. 工作台把候选标记为 `publish_ready`，模型据此向用户报告完成并停在人工审查阶段。

全过程约 642 秒，62 次命令中 15 次非零退出，输入 581 万 token（其中约 565 万为缓存），输出 2.8 万 token。过程成本明显偏高，但当前优先问题仍是内容正确性与深度。

## 内容质量

### 已达到的能力

- **系统身份与演进：** 正确把快照导入放回同一个 QPL 系统，并保留只读分析、分配缺口、早期 Ratio 和生产未知。
- **用户入口：** 能说明从项目根运行 preview/apply、确认令牌和拒绝语义。
- **核心链路：** 已建立 CSV → `SnapshotImportRow` → 当前数据库行 → 差异计划 → 确认令牌 → 事务 UPSERT 的主线。
- **安全写入：** 能解释重新解析、锁表、`FOR UPDATE`、事务、参数化 UPSERT、`ON CONFLICT`、`IS DISTINCT FROM` 与重复导入不刷新时间。
- **状态保护：** 能说明来源字段覆盖、人工确认/执行字段保留，以及同名 Good、Bad、CSV 内选项状态的合并边界。
- **知识融合：** 根入口、领域视图、学习旅程、来源、系统、数据库能力和变更日志同步更新，父知识没有被压缩或删除。
- **隔离性：** 正式知识和产品代码没有被修改，候选可直接整组拒绝。

### 未达到的能力

1. **提交祖先关系判断错误。** `ea10860` 是包含 `c51e232` 实现、并补充报告和夹具的后继提交；报告明确验证实现提交并不构成冲突。模型没有用祖先关系和提交差异核验，反而把可靠证据降级为待确认。
2. **外部 CSV 契约不完整。** 候选没有列出精确 11 列，也没有区分外部 `good_metrics_json`、`bad_metrics_json`、`option_metrics_json` 与内部字段。四字段自然键和七个来源拥有字段虽有概念描述，但不能据此构造或审查真实文件。
3. **指标校验边界过薄。** `METRIC_NUMBER_KEYS`、各层精确字段、整数/布尔类型、`2_147_483_647` 上界以及 `expect_reject`、`actual_reject` 等数量不变量没有完整进入正文。读者无法仅靠知识判断哪类输入会整批拒绝。
4. **固定运行证据内化不足。** 候选保留了 3024→3025、1/1/1、0/0/3、脏批和 stale token，但没有记录状态保护的代表性原值与结果，也没有记录本实现的 Python 26 项、Vue 30 项、类型检查和构建结果；旧分析纵切的 17 项 Python 结果不能替代本次回归。
5. **软件职责链不完整。** `import_models.py`、`SnapshotImportPlan`、`SnapshotImportResult` 未进入知识；CLI、Service、Repository、PGConnector 和快照表虽被提及，却没有形成足以支持修改的完整职责与入口表。
6. **软件架构“声明已更新，正文实际未更新”。** q-003 把既有 `analysis-workbench-architecture-and-implementation.md` 列为规范知识，但该页相对父知识没有变化，仍是分析纵切；系统架构页也没有吸收导入职责。工作台没有识别“登记路径存在但未承载新答案”。
7. **固定日期边界缺失。** 固定运行把 14 天窗口移动到 2026-07-13～2026-07-26，这是验证准备，不是产品自动改日期能力；候选没有说明这个边界。
8. **来源导航仍带旧身份。** 来源页和系统页正文已更新，但标题/描述仍偏向“人工质检分析”，来源页的实际读取范围也没有列出导入文件和验证报告，降低后续追溯效率。

## 与强参考的差异

强参考没有依赖特定目录数量取胜，而是在同一父知识上补齐了三种决定性信息：

- 用 `git merge-base --is-ancestor` 和提交差异确认报告、实现、证据提交的关系；
- 直接从导入模型与常量冻结外部 11 列、内部对象、指标字段和不变量；
- 新建一页明确的快照导入软件架构与实现，将 CLI、models、Service、Repository、PGConnector、表、状态合并和固定运行结果连成可修改的责任链。

候选可以采用不同的知识拓扑，但必须提供同等答案能力。本轮问题不是“没有照抄参考页面”，而是缺失这些答案。

## 下一轮只应修正的 Harness 根因

1. **证据提交关系：** 固定报告指向实现提交、冻结来源是后继证据提交时，必须核验祖先关系和后续 diff；只有实现发生未覆盖变化、提交无祖先关系或报告无法关联环境时才降级。
2. **外部契约冻结：** CSV、API、Schema 等外部契约必须优先读取直接常量/模型，保留真实外部字段名、内部映射、类型与不变量，不能用概念组替代。
3. **软件职责验收：** 一个软件问题只有在候选正文真正解释了必要模型、转换、职责、依赖和修改入口后才能关闭；存在的旧页面不能因被列入路径就算已更新。
4. **代表性运行结果：** 采用固定报告时，正文必须保存本次变化的代表性数值、状态前后值和完整回归范围，并区分验证准备动作与产品能力。
5. **工作台低成本修正：** 单个问题允许合理拆分更多规范落点，检查命令应减少 unit/question 混淆，模板示例不应被误报；这些只用于降低试错，不替代内容要求。

以上均是代码变化回写的一般能力，不应写成 QPL 或某个字段的特例。完成最小修正后，只再跑一次同用例干净 Trial；若仍不能达到 22/24 且全部关键题通过，应停止同题微调并把该能力边界记录为未收敛。
