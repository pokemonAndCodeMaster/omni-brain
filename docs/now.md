# 当前实验工作台

> 最近更新：2026-07-26。

## 当前状态

知识摄入已能在发布前隔离候选并形成局部业务—代码纵切。V9 前向 Trial 证明弱模型会在长文只展示前 24 行后仍声明 `read_full`。V10 已在原工作台中实现 `source-read`：按固定上限连续展示来源、记录哈希和展示进度，并在全文尚未展示时拒绝 `read_full`。当前状态是 `implemented_content_first_v10_awaiting_forward_test`；正式知识仍为空，也没有参考答案或业务评分点进入本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、`source-read` 有界连续展示、Agent 覆盖声明、固定根入口、内容声明契约和结构检查；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- `source-read` 能否让弱模型实际读完其声明全文阅读的关键长文；
- 模型能否保持“机器已完整展示”和“我已理解并内化”的边界；
- 有真实完整展示事实后，来源主题复核能否把快照、Delta、结论执行等材料带回正文；
- 后置消费者能否按上级、主题全貌和用户焦点的原始问题范围判断完整性；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。
