# 当前实验工作台

> 最近更新：2026-07-22。

## 当前状态

M1 已完成三轮 Luna 真实 Trial。机器盘点、候选工作台、发布前隔离、合法表格、唯一产品视图和结构/内容分层取得有限证据，但内容最高仅 12/24，第三轮又退回 10/24：模型没有建立质检—人工质检—验收的逐层全貌，也没有沿真实业务动作读取 Python 实现。当前第四版状态是 `implemented_content_first_v4_awaiting_forward_test`：先优化内容形成流程，正式知识仍为空，也没有参考答案泄漏到本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `ingestion_workspace.py` 的机器来源清单、Agent 覆盖声明、固定根入口、内容声明契约和结构门禁；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 第四版内容主线能否让 Luna 主动补齐上级定位、主题全貌和用户焦点；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。

## 下一动作

先把第四版内容工作流作为新的干净 Harness 基线，再用与前三轮相同的真实摄入需求启动 Luna 前向验证。主要观察模型怎样确定问题主线、选择事实源、建立三层全貌、追踪真实代码并编织产品视图；结果声明、读取收据和结构检查只作为辅助诊断。候选在通过人工内容审查前不发布、不升级能力状态。
