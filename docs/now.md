# 当前实验工作台

> 最近更新：2026-07-22。

## 当前状态

M1 已完成五轮 Luna 真实 Trial。第五轮首次形成质量上层、人工质检全貌、验收规范、软件纵切和逐题答案的紧凑组合，后置消费者也能主动识别 partial；内容由 12/24 升至 15/24，但完整平台模块、验收监控分析、数据库/OBS 公共能力和软件多视图仍不足。当前第六版状态是 `implemented_content_first_v6_awaiting_forward_test`；正式知识仍为空，也没有参考答案泄漏到本项目。

## 当前可用

- OpenCode 原生根路由；
- `ingest-knowledge` 的盘点、候选编织、人工门禁、发布与立即消费流程；
- 面向弱模型的内容主线：先定义读者问题和“上级定位 → 主题全貌 → 用户焦点”，再匹配直接事实源、设计知识地图、从全貌下钻到代码/算法，最后从产品视图实际回答问题；
- `reader-answers.md` 逐题消费页：每个核心问题都必须给出可靠答案、部分答案、明确未知或确实不适用，并限制到产品视图和最多三篇规范页；
- `ingestion_workspace.py` 的机器来源清单、Agent 覆盖声明、固定根入口、内容声明契约和结构门禁；
- 空 OKF Bundle、领域地图和两类产品视图入口；
- 标准 Markdown 相对链接约定与只读链接/入链检查；
- 已有任务案和本地 Git 来源范围能力。

## 当前未证明

- 第六版能否在保留第五轮优点的同时补齐平台/业务模块、验收运行闭环、公共能力页和软件多视图；
- Luna 能否为当前业务与软件结论选择匹配的直接事实源，并沿真实动作下钻 Python 实现；
- 真实材料能否形成高质量规范知识与产品视图；
- 算法细节、现实形态、冲突和未知能否保持准确；
- 用户审查负担是否可接受。
