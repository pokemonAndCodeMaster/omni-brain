# Milestone 参考成果、Harness 蒸馏与晋升闭环

> **状态**：核心方向已获用户批准；文件结构与首轮阈值为 provisional，等待 M1 实例修正。  
> **日期**：2026-07-19。  
> **解决的问题**：让每个 Milestone 既有经过人工审定的当前最佳成果，又能公平检验较弱模型与 Harness，并能用干净、可信的起点继续下一阶段。

## 1. 核心结论

每个 Milestone 同时运行三条隔离轨道：

```text
专家参考轨：相同来源 → 强模型执行 → 用户多轮审查 → 认证参考成果
候选盲测轨：干净 Harness → 非参考模型盲跑 → 候选成果与运行轨迹
优化晋升轨：分层比较 → 定位失败 → 蒸馏进 Harness → 干净重跑 → 晋升
```

认证参考成果是“当前经过证据和人工审查的最佳可用版本”，不是唯一合法文件布局，也不是永远正确的答案。候选若在事实、结构或体验上更好，可以形成参考成果升级提案。

## 2. 三个物理边界

### 2.1 评测者私有面

只保存在设计仓库：

- 冻结任务与来源范围；
- 认证参考成果及版本清单；
- 业务参考答案、允许替代方案、评分规则和反例；
- 专家运行的可观察轨迹和用户审查决定；
- 候选 Trial、差异分析与晋升记录。

候选运行结束前不得通过目录、Git 历史、Prompt、消息或工具输出接触这些内容。

### 2.2 候选生产面

独立 Harness 只包含真实生产会存在的规则、Skills、模板、确定性工具和任务开始前的知识。候选只接收生产等价用户需求、用户明确指定的来源和运行中真实人工决定。

### 2.3 下一阶段认证种子

Milestone 认证后，从参考成果中只提取下游真实需要消费的产物，例如规范知识、配置、代码或已验证运行状态，建立新的干净起始提交。私有答案、Grader、固定覆盖点和专家轨迹不进入种子。

## 3. 认证参考成果包含什么

一个参考成果包至少包含：

| 产物 | 作用 |
|---|---|
| `manifest.yaml` | Milestone、状态、来源版本、Harness 基线、参考版本和关联契约 |
| `outcome/` | 当前最佳最终环境状态；M1 是规范知识、领域地图和产品视图 |
| `review.md` | 用户唯一审查入口和每轮决定 |
| `source-coverage.md` | 实际读取范围、来源权威、能证明与不能证明的事项 |
| `open-questions.md` | 未知、冲突、需要人员或实时系统补充的内容 |
| `accepted-alternatives.md` | 允许候选采用的其他结构、措辞或策略 |
| `consumption-reference.md` | 私有消费问题的参考结论与可接受边界 |
| `teacher-observations.md` | 文件读取、工具调用、检查点、人工介入和成本；不保存隐藏思维过程 |

状态只允许：`draft → under_review → certified → superseded`。认证必须有用户决定和 Git commit；内容更新产生新版本，不覆盖旧认证版本。

## 4. 怎样比较参考与候选

比较不是全文相似度或固定文件路径匹配：

1. **安全和授权硬门禁**：越权读取、来源修改、审批前发布、隐私泄漏、无法回滚；任何一项失败则 Trial 失败。
2. **关键事实和可信边界**：关键事实、算法、不变量、现实形态、冲突和未知；关键错误不能被其他优点抵消。
3. **结构与产品结果**：唯一规范落点、导航、视图、来源追溯和真实消费是否成立。
4. **允许差异**：文件名、页面拆分、措辞、合理工具顺序和参考未覆盖但更优的结果。
5. **过程与成本**：是否无界翻阅、重复返工、错误暂停；人工决策数、纠正数、时延和读取量只在结果正确后比较。
6. **稳定性**：保留单次 Trial；关键安全行为看 `pass^k`，开放质量看多次结果分布，不用一次幸运成功晋升。

候选优于参考时，先提出参考升级，不降低候选得分以维护旧答案。

## 5. 怎样把差异蒸馏进 Harness

只蒸馏跨任务可复用的方法和不变量：

| 反复失败 | 优先落点 |
|---|---|
| 不知道何时触发能力 | 根路由或 Skill description |
| 漏掉稳定步骤或人工暂停 | Skill 工作流 |
| 结果结构反复缺字段 | 模板或状态文件 |
| 格式、链接、安全、完整性可机械判断 | 只读检查器或原子工具 |
| 特定失败需要持续防回归 | 私有 Eval Task / Grader |
| 缺少业务事实 | 知识或人员/系统补知，不修改通用 Skill 猜答案 |

不得把 M1 验收专有事实、私有消费问题或参考措辞复制进通用 Harness。可以保存非测试领域的教学示例；不得用测试答案伪装 few-shot。模型微调、偏好训练或强化学习属于后续可选增强，不是 Harness 可移植性的前提。

## 6. Milestone 怎样固化和晋升

每个 Milestone 冻结五类成果：

1. 一个明确版本的通用 Harness；
2. 一个用户认证的参考成果快照；
3. 私有任务、参考答案、评分契约与反例；
4. 候选 Trial、人工修正和失败分类；
5. 晋升记录：已验证范围、模型与宿主、已知限制、下一阶段认证种子。

晋升同时要求：参考成果已认证；候选从干净环境通过硬门禁和用户结果；重复运行达到本阶段稳定性要求；没有把私有答案蒸馏进生产 Harness；下游种子可从认证成果重建。

## 7. 下一阶段的双轨验证

下一阶段不能只吃一种上游产物：

- **阶段隔离轨**：使用认证种子，判断本阶段组件本身是否有效；
- **端到端轨**：使用上一阶段候选实际产物，判断真实链路能否衔接并承受合理缺陷。

阶段可以先在认证种子上设计和实现，但只有两条轨道都通过，才能声称跨阶段闭环成立。

## 8. M1 的当前应用

1. 保留候选 Harness `890e65f` 作为盲测基线；
2. 在设计仓私有 `eval/reference/m1-knowledge-ingestion-v1/` 生成参考成果；
3. Codex 基于与候选相同的来源工作，用户多轮审查 `review.md`；
4. 认证后冻结 `M1 reference v1`，再开始正式候选盲测；
5. 候选与参考按结果、可信边界、过程和人工负担比较，失败只定向修复 Harness；
6. M1 晋升时，从认证知识快照建立 M2 阶段隔离种子，同时保留候选知识供端到端验证。

当前不设看似精确的质量分数。硬门禁必须全过；人工负担和开放质量阈值在参考轨与首批候选 Trial 有真实数据后共同确定。
