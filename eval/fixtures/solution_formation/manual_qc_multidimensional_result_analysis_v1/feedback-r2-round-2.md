# 人类对第二轮方案的收敛反馈

请继续原位修订 R2，不修改产品代码。

1. `manual_qc` 下不需要再拆 `snapshot` 和 `snapshot_statistics` 两个目录。快照刷新、Repository、对外 Service 和统计规则都强相关，应在同一个 `snapshot` 模块内按文件职责组织。
2. 结果完整性应由接口保证：成功就取齐，取不齐就整体失败并暴露问题。不要增加 `complete`、`loaded` 一类标志，也不要设计局部结果或运行时备用数据路径；这会掩盖正确性问题并增加定位、维护成本。
3. 接口必须清楚说明查询或计算的具体对象。不要只叫 `query`、`catalog`、`export`，也不要让一个万能接口包办完整结果、指标定义、聚合统计和导出等不同职责。
4. CSV 在 Excel 中容易因编码出现中文乱码，快照里还有 JSON 字段。请考虑默认导出 XLSX，并明确固定 JSON、变长问题选项怎样让人直接使用，不要把大段 JSON 塞在一个格子里。
5. 当前没有异步导出的真实需求，不设计导出队列、异步任务或备用导出方式；实际规模证明有必要时再讨论。

其他方案内容基本合理。修订后给出清楚的 R2 确认项和“尚未实施”的边界。
